## 一、分层

```
┌───────────────────────────────────────────────────────────────┐
│  接入层   Web 控制台（单页）  ·  CLI（zw）  ·  MCP（stdio/HTTP）│
└───────────────────────────────┬───────────────────────────────┘
                                │  统一响应 {ok, data} / {ok, code, message, hint}
┌───────────────────────────────▼───────────────────────────────┐
│  控制面 zw-core                                                │
│   profiles CRUD · 生命周期状态机 · 端口池 · 租约 · 审计          │
│   cookie/storage 桥 · 扩展库 · 同步协调 · 健康巡检              │
└───────┬──────────────────────────────────┬────────────────────┘
        │ subprocess                       │ 加密快照（HTTP）
┌───────▼──────────────────┐      ┌────────▼───────────────────┐
│  运行时                   │      │  zw-hub                    │
│  chrome × N（每环境一个） │      │  CAS 存储 · 跨机租约 · 索引 │
│  只监听 127.0.0.1:2100x   │      └────────────────────────────┘
└───────┬──────────────────┘
        │ ws
┌───────▼───────────────────────────────────────────────────────┐
│  CDP 网关（同一个进程，同一个端口 8730）                        │
│  /cdp/{id}/json/*  发现接口 + **地址重写**                      │
│  /cdp/{id}/...     ws 字节级反代                                │
│  短期令牌鉴权 · 单环境并发限制 · 连接审计                        │
└───────────────────────────────────────────────────────────────┘
```

**为什么网关和控制面在同一个端口、同一个进程**：
一个进程就少一个部署单元、少一个故障点、少一次鉴权往返。CDP 的流量特征是"少连接、大帧"，
FastAPI 的 ws 转发完全撑得住（实测 128MB 的帧上限够用）。

## 二、环境状态机

```
          创建
           │
      ┌────▼─────┐
      │ stopped  │◄──────────────┐
      └────┬─────┘               │
        start│                   │stop / 自动重启失败
      ┌────▼─────┐   超时/失败   │
      │ starting ├──────────► failed
      └────┬─────┘
       就绪 │  ▲ 重试
      ┌────▼──┴──┐
      │ running  │
      └──┬────┬──┘
   stop  │    │ 探针连续失败
      ┌──▼──┐ ┌▼────────┐
      │stop-│ │ crashed │
      │ping │ └─────────┘
      └──┬──┘
      ┌──▼─────┐
      │ stopped│
      └────────┘
```

**规则**：
- `restart` = `stop` → **等端口真正释放** → `start`。不做原子重启，因为 Chromium 快速重启会撞 `SingletonLock`。
- `stop` 先试 CDP 的 `Browser.close`，再 `SIGTERM` / `CTRL_BREAK`，宽限期后强杀。
- `crashed` 由巡检判定（连续 `/json/version` 不可达），按 `restart_policy` 决定是否自动重启。
- 同步状态（`clean` / `dirty` / `pushing` / `pulling` / `conflict` / `key_mismatch`）是**正交标记**，不改主状态。

## 三、五条关键数据流

### 3.1 启动一个环境

```
POST /profiles/{id}/start
  → 查本地租约（本进程可重入）
  → 查并发上限、端口池
  → 拼命令行（指纹种子 / 平台 / 代理 / 扩展 / 时区 / 窗口尺寸）
  → fork/exec
  → 轮询 DevToolsActivePort 或 /json/version（≤45s）
  → 登记网关路由（id → 127.0.0.1:21001）
  → 返回完整 ws 地址 + 短期令牌
```

**坑**：
- 无图形会话的 Linux 上必须 `--headless=new`，否则 Chromium 直接报 `Missing X server` 退出。
- 以 root 跑必须 `--no-sandbox`。
- 新版 Chromium 必须 `--remote-allow-origins=*`，否则网关的 ws 被拒。

### 3.2 局域网用 CDP

```
GET /profiles/{id}/cdp
  → 签发短期令牌（只存 sha256）
  → 服务端自己 GET 一次 /cdp/{id}/json/version?token=...
  → 拿到**已重写**的完整 ws 地址返回
客户端 → ws 连网关 → 网关校验令牌 → 反代到 127.0.0.1:21001
```

**为什么要服务端先解析一次**：Playwright 的 `connectOverCDP` 只接受 `http://host:port`
（它会自己拼 `/json/version`）或完整 ws。网关路径里带令牌查询串，直接拼 http 形状会被拼坏。

### 3.3 写 cookie

```
PUT /profiles/{id}/cookies
  → 环境没运行就先启动（可关）
  → 直连本机 21001 的 ws
  → Target.attachToTarget(flatten) 拿 sessionId   ← 关键，浏览器级端点没有 Network 域
  → Network.enable / clearBrowserCookies / setCookies（每批 50 条，失败再逐条重试）
```

### 3.4 跨机推送

```
POST /sync/{id}/push
  → 本地租约（sync）
  → hub 租约（owner = 主机:pid:随机）
  → 保证运行 → CDP 读明文 cookie + localStorage
  → 打包（白名单 + 排黑名单）→ zstd → AEAD 加密
  → PUT /v1/blobs（CAS：该版本已存在即 409）
  → PUT /v1/latest（版本必须单调前进）
  → 写回本机 sync_revision / 口令指纹
```

### 3.5 跨机拉取

```
POST /sync/{id}/pull
  → 本地没有这个环境？→ 从 hub 的 manifest 自动导入（同 id、同指纹种子）
  → 取 latest 与块
  → **先验密钥指纹**（不一致立刻中止，一个字节都不落盘）
  → 解到 staging/（不在正式目录里解）
  → 原子 rename：udd → udd.bak.<rev>，staging/udd → udd
  → 启动浏览器 → CDP 把 cookie 写回去
  → 保留最近 2 份备份
```

## 四、为什么不用现成方案（一句话版）

| 方案 | 为什么不直接用 |
|---|---|
| Roxy | 免费只给 3 个窗口，多的要钱 |
| Donut Browser | 免费给无限环境，但 `run`/`kill` 要 $99/月，而且 CDP 只绑回环 |
| foxprofile | MIT 且好用，但它**不暴露 CDP 端口**（是"我帮你操作页面"的模型） |
| CPM / Fury | 同步做得好，但挂扩展就阻塞 / 无 Linux 版 / AGPL |
| AliasMode | Local API 只回环，Cloud 同步不能自托管 |

详细对比见调研报告（与本仓库同源，`指纹浏览器_REPORT.md`）。

## 五、刻意不做的三件事

1. **不做指纹引擎**。那是跟上游 Chromium 版本赛跑的无底洞，而且开源引擎已经够用。
2. **不做多主（multi-writer）**。跨机同步最大的风险是"两台机器同时用一个号"，多主会让这个概率不为零。
3. **不做 TLS**。按需求，局域网内用明文 HTTP + 包体自身加密。跨公网请走隧道，别开端口。

## 六、容量参考（单机）

| 资源 | 单环境 | 20 个在跑 | 200 个存量 |
|---|---|---|---|
| 磁盘（清洁态） | 15–40 MB | — | 4–8 GB |
| 磁盘（未清理缓存） | 150–400 MB | — | 30–80 GB（需要定期 trim） |
| 内存 | 250–500 MB | 5–10 GB | — |
| 调试端口 | 1 | 20 | — |

实测参考：一个干净环境打包后 **5.6–15 KB**（因为排除了缓存，只留 localStorage / Preferences 等必要文件）。
