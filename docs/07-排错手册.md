# 07 · 排错手册

> 按"现象"查，不用按模块。
> 第一步永远是：`zw doctor`，第二步是看日志（位置见 [08](08-运维与日志.md)）。


---

## 一、先跑这三条

```bash
zw doctor                                   # 9 项环境自检
zw profile list                             # 现在有哪些环境、什么状态
zw profile logs <环境名> --tail 200           # 该环境的 browser.log + profile.log
```

`zw doctor` 会明确告诉你"没找到内核"、"当前内核不是 fingerprint-chromium"、"磁盘余量低于 2GB"
这类**根因**，很多问题到这里就结束了。

## 二、最常见的失败模式（0.2.0 新增）

### `PORT_MISMATCH` — 端口上跑的不是刚启动的浏览器

```
端口 21001 被别的进程（pid=12345）占用，不是刚启动的浏览器。
```

**为什么这个错误值得单独一节**：0.1.0 里没有这个检查，于是它会把**别人浏览器**的 ws 地址
登记成自己的路由，客户端连过去看到的是另一个环境的 cookie。那是会毁账号的事故。
现在宁可启动失败也不冒这个险。

成因与处理：

| 成因 | 处理 |
|---|---|
| 上一次的 chrome 没退干净 | 运维页点「清理孤儿进程」，或 `zw reap` |
| Windows 上端口落进 Hyper-V 保留段 | `netsh int ipv4 show excludedportrange protocol=tcp` 确认，然后改 `.env` 的端口池 |
| 端口池与别的服务冲突 | 换个段，例如 31001–31100 |

### `LAUNCH_TIMEOUT` 且 browser.log 里有 `DevTools listening on ...`

说明浏览器其实起来了，但程序没能确认端口归属。看两件事：

```bash
ss -ltnp | grep <端口>          # 谁在监听
zw profile logs <环境名> --tail 50
```

如果日志里端口与分配的一致，而 `ss` 显示的 pid 就是那个 chrome，那说明清理逻辑误判了，
把这条现象发我。

### `CDP_TIMEOUT` / `CDP_COMMAND_FAILED`

页面卡住（比如弹了原生对话框、页面在死循环）时会出现。

```bash
zw profile restart <环境名>     # 最省事
zw profile probe <环境名>       # 重启后确认指纹还正常
```

### `EXTENSION_IN_USE` / `PROXY_IN_USE`

不是错误，是保护：删扩展/代理前要先从环境里解绑。响应里会列出「还被这些环境使用：xxx」。

```bash
zw profile unbind-ext <环境名> <slug>
zw extension rm <slug> <version>
```

### `IMPORT_INVALID` vs `KEY_FINGERPRINT_MISMATCH`

- `IMPORT_INVALID`：这不是知纹的包（魔数不对/被截断）。
- `KEY_FINGERPRINT_MISMATCH`：包是对的，但主密码不对。

顺序是刻意的：先判断"这是不是我们的包"，再问密码。否则你上传一个随便的文件时会一直被告知"请提供主密码"。

### 指纹体检报了警告，怎么办

| 警告 | 真实含义 | 处理 |
|---|---|---|
| `WebGL 渲染器为空` / `SwiftShader` | 这台机器没有可用 GPU | 换有显卡的机器；这无法在软件层修好 |
| `环境声明平台是 windows，但 navigator.platform 是 'Linux x86_64'` | 内核不认 `--fingerprint-platform` | 换 fingerprint-chromium；系统 Chrome 会忽略这个参数 |
| `环境设定时区 X，但浏览器报告 Y` | 时区没应用 | 确认内核支持 `--timezone`；Linux 上还有 `TZ` 环境变量兜底 |
| `outerWidth/outerHeight 为 0` | headless | 有桌面时别开 headless |
| `navigator.webdriver = true` | 内核没生效 | 同上，换内核 |

> 体检只查**内部自相矛盾**。能不能过真实风控必须去 browserscan / creepjs 实测。

## 三、Windows 专有几条

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动环境报 `PORT_EXHAUSTED` 或 `PORT_MISMATCH` | Hyper-V/WSL 保留了 21001–21100 | `netsh int ipv4 show excludedportrange protocol=tcp`，然后改端口池 |
| `ENGINE_NOT_FOUND` 但明明装了 Chrome | 装在非标准路径 | 在 `.env` 里设 `ZW_CHROME_BIN` 直接指路 |
| 另一台机器连不上 8730 | Windows 防火墙 | `netsh advfirewall firewall add rule name="zhiwen" dir=in action=allow protocol=TCP localport=8730` |
| 路径含中文/空格导致内核参数解析异常 | 内核限制 | 项目放 `C:\dev\zhiwen_brwo` 这类纯英文无空格路径 |
| 中文主机名让租约 owner 变乱 | 早期版本没做 URL 编码 | 0.2.0 已在 hub 侧对 owner 做编码处理；若仍异常可设 `ZW_NODE_ID=pc-a` |

## 四、网关相关

### 客户端拿到 `127.0.0.1:xxxxx` 连不上

说明地址没被重写。检查：客户端连的是**网关地址**（`/cdp/<id>/json/version?token=`），
而不是直接访问内核端口。直连内核端口只能在本机用。

```bash
curl -s "$(zw profile cdp <环境名> --json | jq -r .raw_cdp_json)" | jq -r .webSocketDebuggerUrl
```

期望看到 `ws://<你的主机或IP>:8730/cdp/...`，不是 `ws://127.0.0.1:210xx/...`。

### `ws 连上就被断开（1008 bad-token）`

令牌过期（默认 3600 秒）或不是这个环境的令牌。重新取一次：`zw profile cdp <环境名>`。

### `too-many-connections`

单环境并发 ws 超过 `ZW_CDP_MAX_CONN`（默认 8）。通常是脚本没关浏览器连接就退出。

```bash
zw stats        # 看 cdp_tokens / 路由连接数
```

### 页面操作把我正在看的页面刷掉了

0.2.0 起不会了：页面类操作（导航/截图/执行 JS/localStorage）跑在**专属管理标签页**里。
如果你在旧版本上遇到，升级即可。

### `devtoolsFrontendUrl` 打开是 404

这是刻意的：DevTools 前端页面由浏览器自己托管，网关不提供它。
该字段现在给的是相对路径，不是网关地址 —— 因为给网关地址必然是 404（0.1.0 就是这样）。

## 五、同步相关

### `HUB_UNREACHABLE`

```bash
curl -s http://192.168.3.5:8700/healthz       # hub 活着吗
ping 192.168.3.5
```

### `UNAUTHENTICATED`（来自 hub）

`ZW_HUB_TOKEN` 与 3.5 上 `/opt/zhiwen-hub/.env` 里的不一致。

```bash
ssh 192.168.3.5 'sed -n "s/^ZW_HUB_TOKEN=//p" /opt/zhiwen-hub/.env'
```

### `CIDR_FORBIDDEN`

hub 或 core 配了 `ZW_ALLOWED_CIDRS` 且你的来源不在名单里。这条现在是 **fail-closed**：
配了名单就只放行名单内的，连"解析不出 IP"也会被拒。

### `REVISION_EXISTS`

两台机器各自推、版本号撞了。先 pull 对齐再 push。

```bash
zw sync diff <环境名> --password xxx
zw sync pull <环境名> --password xxx
zw sync push <环境名> --password xxx
```

### `KEY_FINGERPRINT_MISMATCH`（412）

**不要重试**。这是主密码不对，或者这个包不是用当前密码加密的。重试一万次结果一样。

```bash
# 确认这台机器打算用哪个口令
zw sync diff <环境名> --password 你以为是的主密码
# 看 local_pw_fp 与 remote_pw_fp 是否一致
```

### 拉取后 cookie 不见了

按顺序查：

1. `sync pull` 的响应里 `cookie_report.ok` 是多少？`fail > 0` 会有原因。
2. 目标环境的 `cdp_enabled` 是 true 吗？（关了就写不回去）
3. 目标机器上启动的浏览器，`--user-data-dir` 是不是被别的进程占着（SingletonLock）？

### 拉取后环境设置没变

设置只在 `apply_settings=true`（默认）时合并，且只覆盖**启动相关字段**（代理、扩展、窗口、时区、分组、标签），
不会动本地的 `name` / `note`。如果远端本来就没设置过这些，本地保持原样。

## 六、数据与磁盘

### 磁盘疯涨

```bash
zw stats                    # 看 disk_human
zw trim                     # 清理所有已停止环境的缓存
```

想自动清理：给环境设 `trim_on_stop=true`（停止时顺手清缓存），
或者设 `ZW_IDLE_TIMEOUT` 让长期没人用的环境自动停掉。

### 环境目录里的 `udd.bak.*` 是什么

`sync pull` / `import` 换目录前留的备份，默认只留最近 2 份。确认新数据没问题后可以手动删。

### 数据库坏了

```bash
sqlite3 <数据目录>/zhiwen.db "PRAGMA integrity_check;"
```

`zw doctor` 也会报。真坏了：把 `zhiwen.db` 改名备份，重启程序会建新库；
环境目录还在，重新建同名环境指向旧目录即可（但指纹种子是新分配的，等于换设备）。
**所以定期备份整个数据目录。**

## 七、给 AI 的排错指令

把这段直接喂给 agent：

```
知纹出问题了，按这个顺序查，不要跳步：
1. 调 zw_doctor，把每个 ❌ 的详情贴出来
2. 调 zw_list_profiles，找出 state 不是 running/stopped 的
3. 对这些环境调 zw_read_logs（tail=100），重点看 browser.log 的最后 20 行
4. 如果涉及同步，调 zw_sync_diff 看 revision 与 pw_fp
5. 给出结论：是环境问题、内核问题、还是同步密码问题
6. 不要自己执行 reset-fingerprint / delete，先问我
```

## 八、日志里该找什么

日志是 JSON 行，直接 jq：

```bash
# 只看错误
jq -c 'select(.level=="ERROR")' <数据根>/logs/zhiwen.log | tail -20

# 某个环境的全部事件
jq -c 'select(.profile_name=="小红一号")' <数据根>/logs/zhiwen.log

# 审计里看谁动过
curl -s -H "Authorization: Bearer $T" \
  "http://127.0.0.1:8730/api/v1/audit?limit=50" | jq '.data.items[] | [.ts,.action,.result]'
```
