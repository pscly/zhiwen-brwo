## 二、Windows 上按这个顺序做（约 20 分钟）

### 第 0 步：准备

```powershell
# 需要 Python 3.11+（安装时勾选 Add python.exe to PATH）
python --version

# 拿代码
git clone https://github.com/pscly/zhiwen-brwo.git C:\dev\zhiwen_brwo
```

> 路径用纯英文，别放 `C:\用户\张三\...`。

### 第 1 步：一键部署

```powershell
cd C:\dev\zhiwen_brwo
.\scripts\windows\部署.cmd
```

它会：建 `.venv`（有 uv 用 uv，没有退回 `python -m venv`）→ 装依赖 → **随机生成**访问令牌和同步主密码写进 `.env` → 自动找系统 Chrome → 起服务。

**屏幕上会把访问令牌和同步主密码打出来，抄下来。** 主密码丢了远端快照就解不开。
也可以在 `C:\dev\zhiwen_brwo\.env` 里看到。

期望：浏览器打开 <http://127.0.0.1:8730> 能看到控制台，顶栏显示你的主机名与内核版本。

### 第 2 步：换指纹内核（重要，10 分钟）

系统 Chrome 能跑，但**没有 `--fingerprint` 支持**：多个环境之间只有 cookie 隔离，指纹是同一台机器。
要真正"一号一设备"，换成 fingerprint-chromium：

```powershell
$dir = "$env:LOCALAPPDATA\zhiwen\engines"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
cd $dir
Invoke-WebRequest -Uri "https://github.com/adryfish/fingerprint-chromium/releases/download/150.0.7871.186/ungoogled-chromium_150.0.7871.186-1.1_windows_x64.zip" -OutFile fp.zip
Expand-Archive fp.zip -DestinationPath .
Get-ChildItem -Recurse -Filter chrome.exe | Select-Object -First 1 FullName
```

然后在 `.env` 里把 `ZW_CHROME_BIN` 指到这个 `chrome.exe`，重启服务。

> 杀软可能报这个未签名构建，把目录加白名单。
> 国内直连 GitHub 会超时，用代理或网盘（作者给了夸克链接）。

### 第 3 步：自检

```powershell
.\scripts\windows\自检.cmd
```

期望：内核、数据库、访问令牌、数据目录、磁盘余量、并发余量全 `[OK]`；
"指纹内核"这一项在换过内核后应该也变成 OK。

### 第 4 步：全量自检（会真开浏览器，约 2 分钟）

服务在跑着的前提下，**另开一个窗口**：

```powershell
cd C:\dev\zhiwen_brwo
.\scripts\windows\全量自检.cmd
```

期望：`通过 60+ 项，失败 0 项`，失败项为 0；跳过项会写明原因。

### 第 5 步：指纹实测（这一步最值钱，10 分钟）

控制台 → 环境 → 新建（随便起个名）→ 启动 → 行内「更多」→「指纹体检」。
看 `warnings` 有没有告警。然后**在浏览器窗口里**打开这三个站：

1. <https://browserscan.net/>
2. <https://abrahamjuliot.github.io/creepjs/>
3. <https://ip.sb/>

重点看：

| 看什么 | 期望 | 不对怎么办 |
|---|---|---|
| WebGL 渲染器 | 你真实显卡（RTX 3080 之类） | 是 `SwiftShader` / `null` → 机器没有可用 GPU，或启动参数里有 `--enable-unsafe-swiftshader` |
| 时区 vs 出口 IP | 一致 | 在环境设置里改 `时区`，并确保代理出口在同时区 |
| Canvas / 字体 | 不是"自动化"标记 | 见下 |
| `navigator.webdriver` | `false` | 指纹内核没生效，回到第 2 步 |

**把三个站的截图发我** —— 这是决定要不要换内核的唯一依据。

### 第 6 步（可选）：连上同步中心

`.env` 里已经留了注释掉的两行，取消注释并填 3.5 上的令牌：

```
ZW_HUB_URL=http://192.168.3.5:8700
ZW_HUB_TOKEN=<在 3.5 的 /opt/zhiwen-hub/.env 里>
```

重启服务，然后控制台 → 同步 → 填主密码 → 对某个环境点「推送」。
到另一台机器上就能「拉取并导入」。

## 三、明天很可能会遇到的四个问题

### 1. 端口被 Hyper-V 占了

Windows 会预留一段端口给 Hyper-V / WSL，`21001` 可能刚好在里面。

```powershell
netsh int ipv4 show excludedportrange protocol=tcp
```

如果 21001–21100 在保留段里，改 `.env`：

```
ZW_PORT_POOL_START=31001
ZW_PORT_POOL_END=31100
```

现在端口冲突会明确报 `PORT_MISMATCH`（而不是像以前那样把别人的浏览器当成自己的），
所以你会直接看到错误而不是莫名其妙的串号。

### 2. 中文路径 / 空格路径

项目放在 `C:\用户\张三\...` 这种路径下时，某些内核参数解析会出问题。用 `C:\dev\zhiwen_brwo`。
数据目录默认 `%LOCALAPPDATA%\zhiwen`，可以不改。

### 3. 杀软拦 chrome.exe 或拦端口

现象：`ENGINE_EXITED` 或 `LAUNCH_TIMEOUT`。
解决：把引擎目录和 `.venv` 加白名单；看该环境的 `browser.log` 有没有被拦痕迹。

### 4. 想在另一台电脑上用这台机器的浏览器

需要放行 8730：

```powershell
netsh advfirewall firewall add rule name="zhiwen" dir=in action=allow protocol=TCP localport=8730
```

并且 `.env` 里加：

```
ZW_HOST=0.0.0.0
ZW_GATEWAY_PUBLIC_BASE=http://<这台机器的局域网IP>:8730
```

（不设 `ZW_GATEWAY_PUBLIC_BASE` 时程序会自动探测局域网地址，但显式写死最稳。）

## 四、明确**没验过**的东西

老老实实列出来，别当成已通过：

| # | 未验证项 | 影响 | 怎么补 |
|---|---|---|---|
| R2 | **指纹能否过 browserscan / creepjs** | 高 | 第 5 步。这是整套东西有没有意义的判据 |
| R3 | **同种子两次启动的指纹一致性** | 高 | 需要 fingerprint-chromium。这是跨机同步的前提：种子一样，两台机器应该"是同一台设备" |
| R5 | **Windows 上跨机 CDP** | 中 | Linux 上已实测（含 Playwright 接管）；Windows 的入站防火墙可能拦，见上面第 4 条 |
| R6 | **大环境（IndexedDB 很大）会被跳过** | 低 | manifest 里记 `skipped`，控制台同步页会显示 |
| R8 | **带认证的「真实」上游代理握手** | 中 | 中继 → 需 Basic 认证的假上游 → 真 Chrome 加载页 **已验**（803KB 回传、17 条认证头全对）。**没验的只是"你那台真实落地代理"** —— 它只能经前置访问，本仓库所在网络连不到。你点一下「代理 → 检测出口」即可验 |
| R9 | **商店链接装扩展的同一台机器端到端** | 中 | 各环节都有证据：本地假商店真 HTTP（含 302）✓、CRX 去头 ✓、建包设默认 ✓、ungoogled 真机插件执行 ✓、真实 Google 下载 ✓（云电脑 164717 字节）。**没串在同一台机器上跑过** |

### 已经从"未验证"转成"已验证"的（2026-11-17 云电脑 Win10/11 + Chrome 157）

- **原 R1 Windows 实机整体跑通** → 已验：免授权码审批（pending → 服务器点允许 → 客户端自动进入）、
  客户端控制台本机免令牌 / 远程凭机器码（401 与 200 都实测）、远程终端、坏代理被拒并给出可读原因、
  启动打开三个检测页、停止记住标签、再启动恢复且不重复、代理库双向同步。

  **官方 Chrome 137+ 忽略 `--load-extension`**（149/150/157 三种内核 × 有无界面都试过），
  而 **ungoogled-chromium 正常加载**。接口会在 `extensions_active` 里如实回报，
  不再让人以为"插件装好了、其实没加载"。

4. `api.py`（路由顺序陷阱：固定路径必须在通配之前）
