# 远程命令行 · 协议契约（实现前必读）

> 这份文件是**接口形状的唯一来源**。core、hub、面板三方都按它实现，
> 谁要改形状，先改这里。

## 为什么是"设备拉取"而不是"服务器连进去"

客户端可能跑在云电脑/NAT 后面，服务器**连不进去**它的 127.0.0.1。
所以命令走**队列 + 长轮询**：

```
管理员/网页 ──POST 命令──▶ hub 队列
                              ▲
                              │ 长轮询（出站，NAT 也能通）
                          客户端 core ──执行──▶ 本地 shell
                              │
                              └──POST 结果──▶ hub ──▶ 管理员/网页
```

设备侧**不新开任何监听端口**，全部是出站请求。这是安全上最重要的一点。

## 认证

| 方向 | 认证方式 |
|---|---|
| 设备 → hub | 现有的 `X-ZW-Device: <device_id>`（被踢的设备直接 403） |
| 管理员 → hub | 面板会话 cookie，或 `Authorization: Bearer <ZW_HUB_TOKEN>` |

## 一、设备侧（core 调用 hub）

### 1. 取一条待执行命令

```
GET /v1/devices/shell/next?wait=25
X-ZW-Device: zwd_xxx
```

- `wait` 秒内没有命令就返回空（上限 30，默认 25）。长轮询，别用 1 秒一次的忙轮询。
- 设备**只有在本地开关打开时才会调用这个接口** —— 这是"关闭"生效的地方。

有命令：
```json
{"ok": true, "data": {"job": {
  "id": "sh_9f3a1c2b", "command": "ipconfig /all", "cwd": "", "timeout": 60, "created_at": 1794836000.1
}}}
```
无命令：
```json
{"ok": true, "data": {"job": null}}
```
设备被踢：`403`，`code = "DEVICE_REVOKED"`（与现有心跳一致）。

### 2. 回传结果

```
POST /v1/devices/shell/{job_id}/result
X-ZW-Device: zwd_xxx
{"rc": 0, "stdout": "...", "stderr": "", "duration_ms": 123, "truncated": false, "error": ""}
```

- `error` 非空表示**没跑起来**（例如设备侧开关已关、cwd 不存在）。
  此时 `rc` 用 `-1`，`stdout/stderr` 可为空。
- `truncated=true` 表示输出超过上限被截断（保留头部）。
- 返回 `{"ok": true, "data": {"accepted": true}}`。

## 二、管理员侧（面板/网页调用）

### 1. 投递命令

```
POST /v1/devices/{device_id}/shell
{"command": "ipconfig", "cwd": "", "timeout": 60}
```

返回 `{"ok": true, "data": {"job_id": "sh_9f3a1c2b", "status": "queued"}}`

- `command` 必填，长度 ≤ 4000 字符
- `cwd` 可空（空=设备默认工作目录）
- `timeout` 秒，1..600，默认取设备配置（一般 60）
- 设备离线时**也允许投递**，排队等它回来（面板会显示"等待设备"）
- 队列长度上限 200，超出 429 `SHELL_QUEUE_FULL`

### 2. 轮询结果

```
GET /v1/devices/{device_id}/shell/{job_id}?wait=30
```

`status` 取值：`queued` | `running` | `done` | `error` | `timeout` | `canceled` | `expired`

> **隐含约定（改之前两边都要动）**：设备回传的 `error` 字段里若包含
> `TIMEOUT`（大写），hub 会把状态映射成 `timeout` 而不是 `error`。
> 这是 core 的 `shell.py` 与 hub 的 `shell.py` 之间的字符串耦合，
> 协议文档写在这里以免以后有人只改一边。

```json
{"ok": true, "data": {"job": {
  "id": "sh_9f3a1c2b", "device_id": "zwd_xxx", "command": "ipconfig",
  "status": "done", "rc": 0, "stdout": "...", "stderr": "",
  "duration_ms": 123, "truncated": false, "error": "",
  "created_at": 1794836000.1, "started_at": 1794836001.0, "finished_at": 1794836001.2
}}}
```

- 未完成时 `stdout/stderr` 为空串。
- `wait` 秒内变成终态就立即返回，否则原样返回当前状态。
- 找不到：404 `SHELL_JOB_NOT_FOUND`（不同设备的 job 互不可见）。

### 3. 历史

```
GET /v1/devices/{device_id}/shell/history?limit=50
```

返回 `{"ok": true, "data": {"jobs": [ ...同上形状... ]}}`，按 `created_at` 倒序。

### 4. 取消

```
POST /v1/devices/{device_id}/shell/{job_id}/cancel
```
仅对 `queued` 有效（已下发给设备就没法取消了）→ `{"ok":true,"data":{"canceled":true}}`。
已终态返回 `{"canceled": false}`。

### 5. 设备开关状态（给面板显示用）

心跳里带 `shell_enabled`（布尔），落库到 devices 表同名列；
面板设备行据此显示"命令行：开 / 关"。

## 三、core 本地接口（本地控制台 / CLI / MCP 用）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/shell/status` | `{enabled, cwd, timeout, max_output, history_count}` |
| POST | `/api/v1/shell/exec` | `{command, cwd?, timeout?}` → 本地执行，返回同上 job 形状 |
| POST | `/api/v1/shell/enable` | `{enabled: bool}` → 运行时开关 + 持久化 |

`exec` 在开关关闭时也允许（本地操作不受远程开关限制），但要带 `local: true` 标记。

## 四、配置项（core）

| 变量 | 默认 | 说明 |
|---|---|---|
| `ZW_SHELL_ENABLED` | `true` | 是否允许**远程**执行命令（本地 exec 不受影响） |
| `ZW_SHELL_TIMEOUT` | `60` | 单条命令默认超时（秒），上限 600 |
| `ZW_SHELL_MAX_OUTPUT` | `65536` | stdout+stderr 各自上限（字节） |
| `ZW_SHELL_CWD` | 空 | 默认工作目录，空=用户主目录 |

## 四点五、实时终端（WebSocket，0.7.0 起）

上面的队列模式是"一问一答"：命令跑完才有输出。要"边跑边出字 + 保持 cwd +
随时能敲下一行"，必须有一条双向长连接。

```
浏览器/CLI ──WS──▶ hub /v1/console/term/{device_id} ──┐
                                                      ├─ 内存里按 device_id 配对
设备（客户端） ──WS──▶ hub /v1/devices/ws ─────────────┘
```

设备侧依然是**出站连接**，不开监听端口。

| 消息 | 方向 | 作用 |
|---|---|---|
| `{"t":"hello","shell_enabled":true}` | 设备→hub | 上线宣告 |
| `{"t":"open","sid":"…","cwd":"…","timeout":60}` | hub→设备 | 建会话 |
| `{"t":"run","sid":"…","command":"…"}` | hub→设备 | 执行（会话不存在会自动建） |
| `{"t":"out","sid":"…","data":"…"}` | 设备→hub | **流式输出** |
| `{"t":"done","sid":"…","rc":0,"cwd":"…","truncated":false}` | 设备→hub | 一条命令结束 |
| `{"t":"input","sid":"…","data":"…"}` | hub→设备 | 原始 stdin（交互式程序） |
| `{"t":"signal","sid":"…","kind":"interrupt"}` | hub→设备 | Ctrl+C |
| `{"t":"exit","sid":"…","rc":0}` | 设备→hub | 会话进程结束 |
| `{"t":"device_offline"}` | hub→管理员 | 设备没连 WS，请回退到队列 |
| `{"t":"overflow"}` | hub→管理员 | 输出太快，部分内容已丢弃 |

**回退是必须的**：WS 连不上（客户端版本旧、命令行被关、企业防火墙挡升级）时，
界面自动回退到上面的 HTTP 队列。只支持 WS 的话，一断就完全不能用。

### 怎么判断一条命令跑完了

管道没有 TTY，等不到提示符。做法是在命令后追加一个**每次会话随机**的标记：

```
<命令> ; printf '__ZW<tok>_%s__%s__
' "$?" "$PWD"        # POSIX
<命令> & echo __ZW<tok>_!errorlevel!__!CD!__               # Windows cmd /v:on
```

读到标记就同时拿到 `rc` 与 `cwd` —— 所以 `cd` 能跨命令保持。
Windows 上必须 `cmd /v:on`（延迟展开），否则 `%errorlevel%` 在整行解析时就被替换成旧值。

### 限制（如实说）

**这不是真正的 PTY。** `vim`、`htop`、`top` 这类需要终端控制的程序不正常。
需要全屏交互请用 SSH 或远程桌面。解析 Chromium 的私有格式、上 ConPTY，
代价远大于收益。

## 五、安全约定（实现时不能省）

1. **设备不为远程命令新开监听端口**，全部出站。
2. 设备侧执行前**再查一次开关**（纵深防御）：即使队列里已有命令，开关关了也不执行，
   直接回 `error="SHELL_DISABLED"`。
3. 每条命令都写审计日志（谁、哪台设备、命令原文、rc、耗时），
   但**日志里不回显输出内容**（可能含密码）。
4. 超时用进程组杀（Windows `taskkill /T`，POSIX `killpg`），别只杀父进程。
5. 输出按字节截断到上限，`truncated` 标记，不要因为超长把内存吃爆。
6. 面板显示命令输出时**必须转义**（输出里可能有 HTML）。

## 九、**别用远程命令杀承载它的进程**（会自杀）

这一条是实打实踩出来的，写下来免得再犯。

远程命令是由 core 进程执行的（`shell/exec` → 起子进程 → 回传结果）。
所以下面这类命令会**杀死执行它的进程本身**：

```powershell
# ❌ 危险：会把执行这条命令的进程自己也杀掉
Get-Process | Where-Object { $_.ProcessName -like "zhiwen-client*" } | Stop-Process -Force
```

后果不是"命令报错"，而是：

1. 脚本执行到那一行就**中断**，后面的语句（比如"装完新版本再启动"）**根本不会执行**
2. 连接被 reset（`Connection reset by peer`），你看到的是一个网络异常而不是命令结果
3. 如果被杀的是唯一实例，那台机器**再也没有客户端在跑** —— 远程通道彻底消失，
   只能到机器前手动启动，或重启（有开机自启）

更隐蔽的是：主控台上它可能还显示一阵子 `online=True`（最后一次心跳还在阈值内），
看起来"没死"，其实已经没了。`core_alive` 也只反映**最后一次上报**的值。

### 要升级/重启客户端时怎么做

- **如果只是想装新版**：直接把安装器跑起来（`/VERYSILENT /SUPPRESSMSGBOXES`），
  Inno 会自己处理"文件占用"——不要先手动杀进程
- **如果必须先停旧实例**：把"杀进程"和"启动新实例"拆成**两条**独立命令，
  且第一条用 `Start-Process` 起一个**脱离的**小脚本去做（例如
  `Start-Process powershell -ArgumentList '-Command','Start-Sleep 2; Stop-Process ...'`），
  这样它不依赖当前这条命令的进程还活着
- **最稳**：让用户在那台机器上操作一次，或者重启机器（有 Run 键自启）

### 一条判据

> 命令里出现 `Stop-Process` / `taskkill` / `kill` 且目标是**客户端自己**时，
> 先问一句：这条命令由谁执行？它会不会把自己也带走？
