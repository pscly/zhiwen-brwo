# 06 · 同步与加密

> 这一层是整套东西里最容易毁数据的地方。看完这篇你能自己判断"为什么同步完我的号掉了"。

---

## 一、为什么不能直接拷目录

`可核`，三处独立来源都这么说：

| 来源 | 原话 |
|---|---|
| Mirage-Browser | Windows 上 Chrome 用 DPAPI 加密，"换机器或换系统用户后 Cookie 与已保存密码会失效" |
| Fury | "`Cookies` 和 `Login Data` 由 OS keychain（DPAPI / Keychain）加密，复制到另一台机器解不开" |
| AliasMode | "Import works only into an empty Local destination on the same Windows machine and account because Windows DPAPI protects browser secrets" |

**更贵的一课**：Chromium 的 `DecryptString` 解不开时**不报"密钥不可用"，它报"损坏"**，
随后 cookie store 会把整个 eTLD+1 组的 cookie 删干净。
所以"带着别人的 Cookies 文件启动" = 主动销毁自己的登录态。

**知纹的做法**：

```
排除 Default/Cookies、Default/Network/Cookies、Default/Login Data
    ↓
用 CDP 从运行中的浏览器把 cookie 以明文读出来，单独放进 cookies.json
    ↓
目标机解包后，用 CDP 把 cookie 写回去
```

## 二、包里到底装了什么

### 2.1 必带（`INCLUDE`）

```
Default/Local Storage          localStorage
Default/Session Storage        sessionStorage
Default/IndexedDB              站点数据库（有体积上限）
Default/Web Data               自动填充
Default/Preferences            关键：扩展注册、默认设置
Default/Bookmarks
Default/Extension State        扩展的运行状态
Default/Local Extension Settings  每个环境的扩展配置
Default/Service Worker/Database + ScriptCache   SW 注册（不含 CacheStorage）
Local State                    profile 级少量状态
```

### 2.2 永远不带（`SKIP_ALWAYS`）

```
SingletonLock / SingletonSocket / SingletonCookie / lockfile
DevToolsActivePort      ← 带上它，目标机会拿到一个已经死掉的端口
Cache / Code Cache / GPUCache / ShaderCache / GrShaderCache
DawnCache / DawnGraphiteCache / DawnWebGPUCache / download_cache / CacheStorage
Crashpad / Safe Browsing* / CertificateRevocation
WasmTtsEngine / OnDeviceHeadSuggestModel / OptimizationHints / ZxcvbnData
hyphen-data / WidevineCdm / MEIPreload / FileTypePolicies
*.bdic                  拼写词典
*.log（LevelDB 的 000003.log 除外 —— 它是 localStorage 的真数据）
```

> 实测：一个干净环境打包后 **5.6 KB – 15 KB**；不排除缓存的话是几十到几百 MB。

### 2.3 跨机额外排除（`SKIP_CROSS_MACHINE`）

```
Default/Cookies
Default/Network/Cookies
Default/Login Data
Default/Login Data For Account
```

这四样无论怎么处理都跨不了机器，改由 `cookies.json` + CDP 重建。

## 三、包格式（v1）

```
偏移  长度  字段
  0    4   魔数 "ZWBN"
  4    1   格式版本 = 1
  5    1   标志位（bit0 = 正文已 zstd 压缩）
  6    2   保留
  8    4   revision（大端，单调递增）
 12   16   salt（Argon2id 用）
 28    4   argon m_cost（KiB，默认 262144 = 256 MiB）
 32    4   argon t_cost（默认 3）
 36    1   argon parallelism（默认 4）
 37    1   保留
 38    8   key_fp（密钥指纹原始 8 字节）
 46   24   nonce（XChaCha20-Poly1305）
 70    8   正文长度（大端）
 78    N   正文 = AEAD(key, nonce, aad=前 46 字节, zstd(tar))
```

**前 46 字节作为 AAD 参与认证** —— 防止有人改了 `revision` 或指纹种子还让包"看起来合法"。

tar 里包含：

```
manifest.json    清单（人类可读，排错第一眼看它）
cookies.json     CDP 格式的明文 cookie 数组
storage.json     {origin: {key: value}}
udd/**           白名单文件
```

`manifest.json` 示例：

```json
{
  "profile_id": "4c1f…", "name": "小红一号", "revision": 3,
  "created_at": 1794773000.0, "source_node": "psubs3.6",
  "engine_version": "Chromium 150.0.7871.186",
  "fingerprint": {"seed": 281456832, "platform": "host", "brand": ""},
  "cookie_count": 412,
  "storage_origins": ["https://www.xiaohongshu.com"],
  "extensions": [], "files": [{"path": "Default/Preferences", "size": 20771}],
  "skipped": [], "cross_machine": true
}
```

## 四、两种"指纹"，别搞混

| 名字 | 怎么算 | 会不会变 | 用来干什么 |
|---|---|---|---|
| **包密钥指纹** `key_fp` | `sha256(Argon2id(主密码, 包内 salt))[:8]` | **每打一次包都变**（salt 随机） | 判断"这个包我能不能解" |
| **口令指纹** `pw_fp` | `sha256("zhiwen/pw-fingerprint/v1:" + 主密码)[:8]` | **只要口令不变就不变** | 跨机对比"我们用的是不是同一个主密码" |

为什么必须这样拆开：
包内 salt 必须随机且随包走（对端才能派生同一个密钥），所以 `key_fp` 天然每包不同。
如果拿它当"主密码标识"，每次 push 都会显示"密钥不符"，全是噪音。
所以 DB 和 hub 里存的是 `pw_fp`，真正的解密门禁用包内的 `key_fp`。

## 五、硬门禁：密钥不一致必须在落盘前拦住

```python
header = bundle.read_header(blob)
if header.key_fp != expected:
    raise BundleError("KEY_FINGERPRINT_MISMATCH", "……已中止，未改动任何本地文件。")
key = derive_key(password, header.salt, header.kdf)
if key_fingerprint(key) != header.key_fp:
    raise BundleError("KEY_FINGERPRINT_MISMATCH", "……")
# 到这里才开始解密、解包、落盘
```

顺序必须是"先验指纹，再碰任何磁盘"。测试里专门有这一条（`test_wrong_password_rejected_before_write`）。

## 六、落盘必须原子

```
1. 解到 staging/<id>.<rev>.<随机>/
2. 逐文件校验
3. rename(udd → udd.bak.<旧rev>)
4. rename(staging/udd → udd)
5. 保留最近 2 份 udd.bak，其余删
任一步失败：回滚
```

**绝不原地覆盖** —— 中途失败会得到"半新半旧"的环境，比不传更糟。

## 七、CAS 与版本号

```
上传：PUT /v1/blobs/{id}/{rev}
      hub 侧该文件已存在 → 409 REVISION_EXISTS（绝不静默覆盖）
      （客户端可带 X-ZW-No-Cas: 1 显式关闭，一般不要用）

指针：PUT /v1/latest/{id} {revision, force}
      只允许前进；要回退必须 force=true

拉取：GET /v1/latest/{id}  If-None-Match: "v<N>"  → 304 表示没新版本
```

**版本号怎么定**：`max(本地 revision, 远端 latest) + 1`。
这样换了同步中心、换了机器都不会撞号。

## 八、跨机租约

```json
// hub 上的 leases/<id>.json
{"owner":"psubs3.6:1463553:95b05165","kind":"sync","ttl":90,
 "acquired_at":1794773000,"heartbeat":1794773010}
```

规则：

- 抢租约时若有人持有且未过期 → `409 PROFILE_BUSY`
- 持有期间每 30 秒续一次心跳
- 崩溃后 TTL（默认 90 秒）过期，别人可以接管
- **本地还有一层租约**（`<环境目录>/lease.json`），防止同一台机器上两个进程同时动手
- 同一进程内可重入（`sync.pull` 持 sync 锁，内部又要 start 拿 run 锁，这是合法嵌套）

## 九、冲突处理

| 情况 | 行为 |
|---|---|
| 远端 revision 更高，本地 clean | 直接拉 |
| 本地 dirty 且远端更高 | `sync_state=conflict`，两边都不动，等你决定 |
| 想以远端为准 | `pull(force=true)`，本地先备份成 `udd.bak.<rev>` |
| 想保留本地 | 直接 `push`，版本号会取 max+1 |

**永远不自动合并。** 两个浏览器环境的 cookie 合并没有正确语义。

## 十、加密参数和"够不够用"

| 项 | 取值 | 说明 |
|---|---|---|
| KDF | Argon2id，m=256MiB，t=3，p=4 | 单次派生 0.4–1.2 秒，可接受 |
| AEAD | XChaCha20-Poly1305 | 192 位随机 nonce，不需要维护计数器 |
| 传输 | 局域网明文 HTTP | 按需求，不依赖 TLS |
| 机密性来源 | 包体本身是密文，hub 解不开 | hub 只存不读 |
| 完整性来源 | AEAD 认证标签 + 46 字节 AAD | 改一个字节就解不开 |
| 可选加固 | `ZW_REQUIRE_SIGNATURE=1` + HMAC 请求签名 + 时间戳 | 防篡改/防重放，局域网一般不开 |

**它不防什么**：不防"有人能物理访问你的机器"、不防"主密码被猜到"、不防"传输过程中被完整重放"
（后者需要开签名）。局域网场景下这是合理取舍。

---

## 十一、主密码的正确用法

| 项 | 建议 |
|---|---|
| 长度 | ≥12 字符，别用站点密码 |
| 存放 | 环境变量 `ZW_SYNC_PASSWORD`，或每次请求带 `password` |
| 绝不 | 写进配置文件、写进 git、写进日志（代码里已做过滤） |
| 换密码 | 需要逐包重加密（`zw sync rekey` 尚未实现，见待办） |
| 忘了 | 远端快照解不开；**本地环境不受影响**，重新 push 一份即可 |

## 十二、验收清单（改动这一层前请逐条过）

- [ ] 同机 push → pull，登录态完好
- [ ] A 机 push，B 机 pull，打开站点不掉登录
- [ ] B 机 pull 后指纹种子与 A 一致
- [ ] 用错主密码 → `412 KEY_FINGERPRINT_MISMATCH`，本地文件 mtime 未变
- [ ] 解包后 `tar -tzf` 里**没有** `Default/Cookies`、`Network/Cookies`、`Login Data`、`DevToolsActivePort`
- [ ] 解包后没有任何 `Cache*` 目录
- [ ] 单包 ≤ 100 KB（干净环境）
- [ ] 两个客户端同时 push → 第二个 `412/409` 而不是静默覆盖
- [ ] pull 到一半 kill -9 → 重启后本地环境完好
- [ ] 400+ cookie 的环境往返一次，`fail` 计数为 0（或全部是 expired）
