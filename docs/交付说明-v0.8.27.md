## 三、这轮最值得说的一条技术结论

**Chromium 从不解析 `--proxy-server` 里的 userinfo。**

| 给 Chrome 的写法 | 代理端收到什么 |
|---|---|
| `socks5://user:pass@host:port` | **握手记录为空** |
| `socks5://host:port` | 正常握手 |
| `http://127.0.0.1:<中继端口>` | 正常，且上游收到**带凭据**的握手 |

这比"认证失败"更危险：认证失败至少连不上；凭据被丢弃后 Chrome 会**把流量直连出去**，
你以为在走代理，实际在裸奔。

所以带凭据的代理**一律走本机中继**：

```
Chrome ──无凭据──► 127.0.0.1:<中继端口> ──带凭据──► 上游代理 ──► 目标
```

真机记录（经中继访问 example.com）：

```
VER=5 METHODS=[0, 2]
  AUTH user=b'cf1b481103' pass=b'51ec63a321'
  CONNECT example.com:443
```

**结论：不需要单独的 Firefox 引擎。** 你那条是条件句（"如果 Chrome 支持不好"），
而支持不好的部分已经由中继补上了。
