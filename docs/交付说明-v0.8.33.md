## 三、一条值得记住的技术结论

**Chromium 从不解析 `--proxy-server` 里的 userinfo。**

| 给 Chrome 的写法 | 代理端收到什么 |
|---|---|
| `socks5://user:pass@host:port` | **握手记录为空** |
| `socks5://host:port` | 正常握手 |
| `http://127.0.0.1:<中继端口>` | 正常，且上游收到**带凭据**的握手 |

认证失败至少连不上；凭据被丢弃后 Chrome 会**把流量直连出去** —— 你以为在走代理，实际在裸奔。所以带凭据的代理一律走本机中继，不需要单独的 Firefox 引擎。
