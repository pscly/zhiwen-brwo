# 11 · 客户端与服务器端

> 一句话：**客户端只要一个服务器 IP，服务器端可以按机器码踢掉任何一台电脑。**
>
> 这一篇讲的形态和 [快速开始](01-快速开始.md) 里的"单机自用"不同 ——
> 那是每台机器各跑一套；这里是"一台服务器 + 若干客户端"。

---

## 一、两张图看懂

```
┌────────────────────────────────────────────┐
│  你的服务器（例如 192.168.3.5）              │
│                                            │
│  zw-hub  :8700                             │
│   · 设备注册表（谁连过、能不能用）           │
│   · 加密快照存储（登录态同步）               │
│   · 跨机租约                                │
│  /panel  管理面板 ← 踢下线、改备注、看事件    │
└───────────────▲────────────────────────────┘
                │  局域网 HTTP
     ┌──────────┴──────────┬──────────────┐
     │                     │              │
┌────┴─────┐        ┌──────┴────┐   ┌─────┴────┐
│ Windows  │        │  另一台   │   │ 再来一台 │
│ 客户端   │        │  客户端   │   │ 客户端   │
│ · GUI    │        │           │   │          │
│ · 内置   │  ← 每台都跑本机的浏览器（指纹必须在本机）
│   core   │
└──────────┘
```

**关键认知**：浏览器永远跑在客户端本机（指纹、GPU、cookie 都是本机的），
服务器端管的是「**谁能用、谁被踢**」和「登录态放哪」，不是代替执行。

## 二、服务器端部署（一次性）

```bash
# 在服务器上（已部署好 Docker）
git clone https://github.com/pscly/zhiwen-brwo.git && cd zhiwen-brwo
bash scripts/deploy-hub-35.sh          # 幂等，可反复跑
```

部署完：

| 地址 | 用途 |
|---|---|
| `http://<服务器>:8700/healthz` | 存活检查 |
| `http://<服务器>:8700/panel` | **管理面板**（登录 `pscly` / `REDACTED_PANEL_PASSWORD`） |

**改账号密码**：编辑 `/opt/zhiwen-hub/.env`：

```
ZW_PANEL_USER=pscly
ZW_PANEL_PASSWORD=换成你的密码
```

然后 `cd /opt/zhiwen-hub && sudo docker compose up -d`。

> 默认**不需要对接码**。准入靠设备注册表：每台电脑都要注册成设备，服务器上看得见、能踢。
> 想更严就把 `.env` 里的 `ZW_HUB_TOKEN` 取消注释并填一串随机值 ——
> 那样客户端会多出一个「对接码」输入框。

### 加到自己的主页（可选）

如果服务器上有 Dashy/导航页，把面板地址加进去即可。仓库里带了一个幂等脚本：

```bash
# 在服务器上执行（会先备份 config.yml）
python3 - <<'PY'
import yaml, subprocess, time
p = "/root/mnt2/mydocker2/Dashy/config.yml"   # 按你的实际路径改
cfg = yaml.safe_load(subprocess.run(["sudo","cat",p],capture_output=True,text=True,check=True).stdout)
sec = next((s for s in cfg["sections"] if s.get("name")=="本地资源"), cfg["sections"][-1])
sec.setdefault("items", []).append({"title":"知纹 · 服务器端","url":"http://192.168.3.5:8700/panel",
                                    "description":"设备管理 / 踢下线","id":"0_113200_zhiwen"})
subprocess.run(["sudo","cp",p,p+".bak."+str(int(time.time()))],check=True)
open("/tmp/new.yml","w").write(yaml.safe_dump(cfg,allow_unicode=True,sort_keys=False))
subprocess.run(["sudo","cp","/tmp/new.yml",p],check=True)
print("已写入")
PY
sudo docker restart Dashy
```

## 三、客户端：装完只要填一个 IP

### Windows

1. 从 [Releases](https://github.com/pscly/zhiwen-brwo/releases) 下载 `知纹客户端-Windows.exe`
2. 双击运行（首次可能被 SmartScreen 提示 → 「更多信息」→「仍要运行」）
3. 在输入框里填服务器地址，例如 `192.168.3.5:8700`
4. 点「连接并开始」

它会自动：生成机器码 → 注册到服务器 → 起本机浏览器服务 → 用默认浏览器打开控制台
`http://127.0.0.1:8730`。

**不需要对接码**（服务器没设 `ZW_HUB_TOKEN` 时）。服务器要求的话，界面会自动多出一个输入框。

### Linux

```bash
chmod +x zhiwen-client-Linux-x86_64
./zhiwen-client-Linux-x86_64
```

### macOS

解压后右键「打开」（未签名，直接双击会被 Gatekeeper 拦）。

### 地址怎么写都行

| 你填的 | 实际连的 |
|---|---|
| `192.168.3.5` | `http://192.168.3.5:8700` |
| `192.168.3.5:8700` | `http://192.168.3.5:8700` |
| `HTTPS://example.com` | `https://example.com:8700` |
| `hz.example.com:1234` | `http://hz.example.com:1234` |

不带端口时默认 `8700`。协议大小写不敏感。

### 配置文件在哪

| 系统 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\zhiwen-client\client.json` |
| Linux | `~/.config/zhiwen-client/client.json` |
| macOS | `~/.config/zhiwen-client/client.json` |

里面有**机器码**和**对接码**（如果有）。权限设成 `0600`，别发给别人。

> **删掉这个文件 = 变成一台"新机器"**。这是绕过踢下线的唯一方式，
> 但服务器上会多出一条新设备记录，反而更容易被发现。

## 四、机器码与踢下线

### 机器码怎么来的

客户端首次启动生成一个随机 ID（`zwd_` + 32 字符），存在本地配置里，之后一直用。

**为什么不用网卡 MAC**：

1. 无线网卡/虚拟网卡一堆，选哪个都能被改；
2. 换 USB 网卡就"变成新机器"，对自用场景纯属找麻烦；
3. Windows/macOS 上都拿不全，还要多装依赖。

随机 ID + 服务器侧可撤销，安全性和可用性都更好。

### 踢下线

管理面板 → 设备列表 → 找那台 → 「踢下线」。

之后：

- 它的**心跳**返回 `403 DEVICE_REVOKED`
- 它的**注册**返回 `403`（重连不能自愈）
- 它的**同步**（用 `X-ZW-Device` 头）返回 `403`
- 客户端界面会立刻弹出提示「这台电脑已被服务器端移除」

**本机已开着的浏览器还能继续用**（那是本地进程，服务器管不着），
但它再也同步不了任何东西。这是刻意的取舍：踢下线控制的是"服务器资源与登录态"，不是"杀掉你的进程"。

随时可以点「恢复」放回来，下一次心跳（≤60 秒）就生效。

### 面板上还能做什么

| 操作 | 说明 |
|---|---|
| 改名（label） | 只改面板显示，例如把那台改成"客厅主机" |
| 删除 | 只删服务器记录。那台下次启动会作为新设备重新出现（机器码还在本地）。**想永久禁止用踢下线** |
| 看事件 | 谁注册了、谁被踢了、谁恢复了，都留痕 |

## 五、只填 IP 安全吗

这是合理的疑问，如实说清楚：

| 风险 | 现状 | 怎么收紧 |
|---|---|---|
| 局域网里任何人都能注册成设备 | 是（默认 `auto_approve=true`） | 设 `ZW_DEVICE_AUTO_APPROVE=false` → 新设备停在 `pending`，要在面板里点放行 |
| 别人知道你的服务器地址就能连 | 是 | 设 `ZW_HUB_TOKEN` → 需要对接码；或配 `ZW_ALLOWED_CIDRS` 限制来源网段 |
| 传输明文（HTTP） | 是 | 快照包本身是 AEAD 密文，hub 解不开；跨公网请走隧道，别直接开端口 |
| 被踢的设备删配置就能重新注册 | 是 | 关掉 `auto_approve`，这样新设备必须你手动放行 |

**这不适合暴露到公网。** 设计的场景是：自己家里的局域网，或者通过 EasyTier / WireGuard 这类隧道连进来。

## 六、验证这套东西是好的

```bash
# 服务器端（在服务器上或任意能访问的机器上）
curl -s http://<服务器>:8700/v1/enroll-info | jq .
# 期望："token_required": false, "auto_approve": true

# 客户端侧（源码运行时）
ZW_CLIENT_HOME=/tmp/zwtest python - <<'PY'
from zw_core import client
base = client.normalize_server("<服务器>:8700")
print("探测:", client.probe_server(base))
did = client.ensure_device_id()
print("注册:", client.enroll(base, did, app_version="0.3.0")["device"]["status"])
print("心跳:", client.heartbeat(base, did)["device"]["online"])
PY

# 打包产物自检（不依赖图形界面，CI 每次构建都跑）
./知纹客户端.exe --selftest        # Windows
./zhiwen-client --selftest         # Linux
```

`--selftest` 会检查：依赖是否都打进去了、控制台页面在不在、AEAD 能不能往返、
Argon2 能不能派生、配置目录能不能写、机器码能不能生成、地址能不能规范化。

> 这条命令是专门为"下载后双击没反应"这类问题准备的 ——
> 在命令行里跑一次，缺什么会直接告诉你，不用猜。

## 七、从源码跑（开发用）

```bash
# 服务器端
cd hub && sudo docker compose up -d --build

# 客户端（有图形界面）
.venv/bin/zw-client

# 客户端（无图形界面的机器，走问答模式）
.venv/bin/python -m zw_core.client
```

没有 tkinter 的环境会自动退回到问答模式，不会崩。

## 八、常见问题

**问：双击 exe 没反应？**
命令行里跑 `知纹客户端.exe --selftest`。如果也跑不起来，说明包有问题（把输出发我）；
如果 selftest 全过但窗口不出来，多半是杀软拦了 GUI 进程，看它的拦截记录。

**问：填了 IP，提示"连不上"？**
按顺序查：服务器地址对不对 → 那台机器上 `curl http://<IP>:8700/healthz` 通不通 →
服务器防火墙有没有放行 8700 → 客户端那台机器的代理/VPN 有没有把局域网流量劫走。

**问：提示"这台电脑已被服务器端移除"？**
去管理面板恢复它。或者删本机 `client.json` 重新注册（会变成新设备，面板上能看两行）。

**问：换电脑了，登录态怎么带过去？**
客户端连同一个服务器后，在控制台 → 同步 → 推送；新电脑拉取即可。
这部分和 [同步与加密](06-同步与加密.md) 讲的是同一套机制。

**问：能不能不用服务器，纯单机？**
能，就是 [快速开始](01-快速开始.md) 那一套。客户端只是把"填 IP + 自动注册"包了一层，
不连服务器时直接用 `zw serve` 也一样工作。
