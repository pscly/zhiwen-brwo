# 14 · 远程命令行

> 一句话：**服务器（或网页）能让这台电脑执行命令**，默认开着，客户端里可随时关。

## 它是干什么的

不是 SSH，也不是远程桌面。它解决的是**AC 场景**：

- 在 3.5 的管理面板里，直接对某台云电脑执行 `ipconfig`、`tasklist`
- 用网页/脚本调接口起一个 CDP 调试会话，再跑两条命令把环境准备好
- 客户端那边的人说不清哪里坏了，你在面板上敲 `zw doctor` 看输出

## 架构：设备主动拉，服务器不连进去

```
你（面板/网页）── 投递命令 ──▶ hub 队列
                                  ▲
                                  │ 长轮询（出站，NAT/云电脑都能通）
                             客户端 core ──执行──▶ 本地 shell
                                  │
                                  └── 回传结果 ──▶ hub ──▶ 你
```

**设备不新开任何监听端口。** 这一步是刻意的：跑在云电脑上的客户端没有公网 IP，
服务器根本连不进去；而且"设备主动外连"天然绕过了 NAT 与家用防火墙。

## 怎么用

### 在面板里（最直观）

1. 打开 `http://<服务器>:8700/panel`，登录
2. 设备行点 **终端**
3. 输入命令，回车

输出区会显示命令、stdout、stderr（暗红色）、退出码与耗时。
`↑` / `↓` 翻本次会话的历史。设备离线时也能投递，命令会在它上线后执行。

### 用接口（写脚本 / 给 AI 调）

```bash
# 1. 登录拿 cookie
curl -c /tmp/ck -X POST http://192.168.3.5:8700/panel/api/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"你的密码"}'

# 2. 投递
JOB=$(curl -s -b /tmp/ck -X POST http://192.168.3.5:8700/v1/devices/<机器码>/shell \
  -H 'Content-Type: application/json' \
  -d '{"command":"ipconfig /all","timeout":30}' | jq -r .data.job_id)

# 3. 等结果（wait 秒内变成终态就立即返回）
curl -s -b /tmp/ck "http://192.168.3.5:8700/v1/devices/<机器码>/shell/$JOB?wait=30" | jq .data.job
```

### 在客户端本机

```bash
zw shell "ipconfig /all"          # 本地执行，不经过服务器
zw shell-status                   # 看开关与代理状态
```

本地执行**不受远程开关限制** —— 那个开关管的是"服务器能不能让这台机器执行命令"。
本地都不让用的话，出问题时你就没法排查了。

## 开关

客户端底部有「允许远程命令行」勾选框，**默认开**。

关掉之后：

1. 客户端**根本不去服务器拉命令**（不是"拉了不执行"）
2. 即使命令已经拉到本地、正在执行前一刻被关掉，也**不会执行**，直接回
   `SHELL_DISABLED`

关掉只影响远程；本机控制台、`zw shell`、CDP 都不受影响。

## 安全边界

这个功能本质是"远程执行命令"，所以要说清楚它挡什么、不挡什么。

| 项 | 现状 |
|---|---|
| 谁能投递命令 | 面板会话（登录后）或持有 `ZW_HUB_TOKEN` 的调用方 |
| 传输 | 局域网内 HTTP；快照包是加密的，但**命令行内容不加密**，跨公网请走隧道 |
| 哪个来源能访问 | 配了 `ZW_ALLOWED_CIDRS` 就只放行名单内网段 |
| 设备侧闸门 | 客户端开关，默认开，随时可关 |
| 超时 | 默认 60 秒（可调，上限 600） |
| 输出上限 | 默认 64KB / 每个流，超出截断并标记 |
| 审计 | 每条命令都记日志（谁、哪台、命令原文、rc、耗时）；**不记输出内容** |
| 进程清理 | 超时按进程组杀（`taskkill /T`、`killpg`），不留孤儿 |
| 交互式命令 | 不支持（`vim`/`ssh` 需要 TTY）。用远程桌面或 SSH |

**它不做的**：不做命令白名单、不做用户分级。也就是说，能登录面板的人就能在这台
电脑上执行任意命令。这是刻意的取舍 —— 需求是"方便自己管机器"，加白名单只会
让"临时排查"变成"先改配置"。前提是：**面板别暴露到公网，密码别用默认的**。

## 常见问题

**问：面板上终端输入框是灰的？**
那台电脑的「允许远程命令行」被关了（或它从没上报过状态）。去客户端里打开。

**问：命令投出去了，一直"等待设备执行"？**
设备离线，或它的开关关着。队列里的命令会等它回来 —— 但只在开关打开时才被执行。

**问：`vim` / `top` 这类命令没反应？**
交互式命令拿不到终端，会立刻退出。这是设计上的限制。

**问：Windows 上中文乱码？**
执行器会依次尝试 UTF-8 / GBK / 系统代码页解码，一般不会乱。
如果确实乱，先把控制台切成 UTF-8：`chcp 65001`。

**问：能执行 `powershell` 吗？**
能，`powershell -Command "..."` 就行。默认 shell 是 `cmd.exe`。
