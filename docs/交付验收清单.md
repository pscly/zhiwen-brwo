## 〇、内核：默认 ungoogled-chromium，自己装

这是 0.7.72 之后的**最大变化**，先看这一节，否则你会疑惑"插件为什么没生效"。

| 验法 | 应该看到 |
|---|---|
| 打开控制台 →「运维」页 | 顶部有一张「内核」卡片：策略 `ungoogled`、路径、版本、**能否加载扩展**、下载代理 |
| 没有内核时新建/启动环境 | 后台**自动下载**（150–200MB），卡片上显示进度 ✅ 真机端到端验过：自动发现本机 `21080` → 下载 141MB → sha256 校验 → 解包 → `Chromium 156.0.8078.79`，能加载扩展 |
| 点卡片上的「下载内核」/ 桌面端「扩展包」面板里的「下载内核」 | 同样触发下载；桌面客户端「本机状态」里也有一格「内核」显示 `可加载扩展` / `缺失` / `下载 xx%` |
| 命令行 | `zhiwen-client engine status` / `engine install` |

**为什么必须换**：官方 Google Chrome **137 起忽略 `--load-extension`**（149/150/157 实测都不加载），
插件只是被"放进环境"、浏览器根本不认。要插件真生效就得用 ungoogled 系内核。

国内网络：程序会**自动探测**本机常见代理端口（7890/7891/7892/21080/7897/1080/10808），
探测是真的发一次请求（不只看端口开着）；也可以显式写 `ZW_DOWNLOAD_PROXY=http://127.0.0.1:21080`。

> 想要"每个环境像不同设备"（不只是 cookie 隔离），再加 fingerprint-chromium：
> 它是 ungoogled 的分支、额外提供 `--fingerprint`。把目录放进 `<数据目录>/engines/` 即可，
> `policy=ungoogled` 会自动接受它（带 `ungoogled` 或 `fingerprint` 字样的内核都算去谷歌家族）。

## 一、代理导入（需求原文的 `socks5://user:pass@host:port`）

| 验法 | 应该看到 |
|---|---|
| 控制台「代理」→「导入代理」，粘一串带密码的 socks5 | 导入成功，列表里 IP/端口**完整可见**，密码显示为 `***` |
| 再粘一次同一串 | 提示重复跳过，不会多出一条 |
| 粘 `http://127.0.0.1:7890` | 也支持（不只 socks5） |
| 故意写错（如 `66.80.12 0.66:20000` 中间多空格） | 被拒，并给出**可读原因** ✅ 真机验过 |
| 看环境的「代理」列 | 绑了**代理库**的环境显示库里的地址（如 `socks5://66.80.12.66:20000`），**不是「直连」** ✅ 0.7.83 修过：之前读空字段会显示成「直连」，与实际相反 |
| 代理 URL 带密码时看日志 / `/api/v1/engine` 响应 | 一律 `***@`，**不出现密码原文** ✅ 0.7.79 修过三处泄露 |

支持链路代理：`前置,落地` 两段写法（前置负责连，落地负责出口）。

## 二、客户端控制台：本机免令牌 / 远程凭机器码

| 验法 | 应该看到 |
|---|---|
| 在**装有客户端的那台机器**上打开 `http://127.0.0.1:8730` | **直接进**，不弹令牌框 ✅ 真机验过（`auth_required=false`，host 是 `0.0.0.0`） |
| 从**另一台机器**打开 `http://<它的IP>:8730` | 要求输入**机器码**，文案就是「机器码」✅ 0.7.82 用真浏览器从 LAN IP 验过：非回环 401 → 输入 `zwd_…` → 登录层隐藏、控制台渲染 |
| 改端口：`zhiwen.env` 里写 `ZW_PORT=8731` 后重启 | 监听变成 8731 ✅ 0.7.85 修过：客户端原来只读自己的 JSON 配置、**不认 `ZW_PORT`**，文档说可改却不起作用 |

> 安全默认：**没配 `ZW_ADMIN_TOKEN` 也没配 `ZW_DEVICE_ID`** 时，`ZW_HOST=0.0.0.0`
> 会被强制降级成 `127.0.0.1` —— 这是防止"没锁的门对外开着"。

## 三、创建完浏览器后还能改代理

| 验法 | 应该看到 |
|---|---|
| 建一个环境 → 启动 → 点「代理」改成另一条 → 重启 | 新代理生效 ✅ 真机验过 |
| 改成**不带密码**的代理 | 命令行是 `--proxy-server=socks5://host:port`（直连上游）✅ |
| 改成**带密码**的代理 | 命令行变成 `--proxy-server=http://127.0.0.1:<端口>`（本机中继代填凭据），并给一条说明 ✅ |

## 四、启动后先恢复上次网页，再加检测页

| 验法 | 应该看到 |
|---|---|
| 新建环境 → 启动 | 自动打开 3 个检测页 ✅ 真机 CDP 读到 3 个 page |
| 在里面多开几个网页 → 停止 | 返回 `remembered: {saved: N}` ✅ 真机 `saved: 3` |
| 再启动 | 恢复上次那些页 + 检测页，**不重复** ✅（0.7.64 修过 `ip123.in` 跳转导致的重复） |

三个检测页与用途（都实测 200）：

| 网址 | 看什么 |
|---|---|
| `browserleaks.com/ip` | 出口 IP、WebRTC 是否泄漏真实 IP |
| `ip123.in` | 中文 IP 干净度：欺诈评分、代理/VPN 特征、原生/机房 |
| `abrahamjuliot.github.io/creepjs/` | 浏览器指纹（FP ID、fuzzy hash、时区语言一致性） |

## 五、插件及其数据打包、默认带上、**可关闭**

| 验法 | 应该看到 |
|---|---|
| 「扩展包」面板 →「从 Chrome 目录导入」→ 点「**扫描本机**」 | 列出本机所有可导入的浏览器（带名字和扩展数）✅ 云电脑 Windows 实测：扫到 Edge(2)/Chrome(1) |
| 选一条 → 勾「设为默认」→ 导入 | 返回 `extension_count>0`、`is_default=true` ✅ `as_default` 真机确认生效（0.7.68 修过它失效） |
| 新建一个环境 | **自动带上**那些扩展 ✅ 真机：新环境 `extensions` 里就有 |
| 想要一个**干净环境**：新建时取消勾选「带上默认扩展包」 | 新环境 `extensions` 为空 ✅ 0.7.88/0.7.89 补的开关（API `with_default_packs=false` + 网页控制台勾选 + 桌面浮层勾选三处都有）。实测：默认建 `['开关自检扩展']` vs 关闭建 `[]` |
| 启动后想看插件到底加载没 | 环境详情里的 `extensions_active` 如实说明 ✅ 官方 Chrome 157 判 `false`（内核忽略 `--load-extension`）；换成 ungoogled 后判 `true` |

> ⏳ **只差这一步需要你**：RXYCDP 装在你的电脑上（云电脑翻遍 C/D 盘确认没有）。
> 在你机器上点一次「扫描本机」，选 RXYCDP 那条导入即可。
> 详细步骤见 [RXYCDP导入指引](RXYCDP导入指引.md)。

## 九、当前明确**没有**做的事（如实说明）

| 项 | 状态 |
|---|---|
| 指纹能否过 browserscan | **未验证** —— 需要 fingerprint-chromium 内核 + 真实站点打分 |
| fingerprint-chromium 的种子一致性 | **未验证**（这台机器上没有该内核） |
| 带认证的**真实**上游代理握手 | **未验证** —— 你的落地代理只能经前置访问，本仓库所在网络连不到 |
| Firefox 引擎 | **不做** —— Firefox 没有 CDP；改用本机 relay 解决认证代理，不需要换内核 |
| `zw sync rekey`（换主密码逐包重加密） | **未实现** —— 碰主密码与加密快照，属危险区，需要你明确要求 |
| hub 多用户 / 权限 | **未实现** |
| macOS 内核自动下载 | **不支持** —— 上游没有可用的 macOS 构建；可设 `ZW_ENGINE_URL` + `ZW_ENGINE_SHA256` 自己指 |
