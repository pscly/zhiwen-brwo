# 03 · 部署指南

> 三种部署形态，按你的实际情况选。
> 推荐：**hub 在 3.5（Docker）+ core 在 Windows（裸装）+ 以后再加节点**。

---

## 一、拓扑总览

```
        ┌──────────────────────────────────────────────┐
        │ 192.168.3.5 · zw-hub（Docker，一个容器一个卷）│
        │  :8700  同步中心：加密快照 + 租约 + 索引      │
        └───────────────▲──────────────────────────────┘
                        │ 局域网 HTTP（包体自带 AEAD）
        ┌───────────────┴───────────────┬──────────────┐
        │                               │              │
┌───────┴────────┐            ┌─────────┴──────┐  ┌────┴─────────┐
│ Windows 主开发机│            │ 192.168.3.6    │  │ 以后再加的机器 │
│  zw-core :8730 │            │  zw-core :8730 │  │              │
│  浏览器 × N     │            │  浏览器 × N     │  │              │
│  Web 控制台     │            │  （无 GPU，只跑 │  │              │
│  MCP 服务       │            │   无头任务）    │  │              │
└────────────────┘            └────────────────┘  └──────────────┘
```

**关键约束**：承担"真人身份"的环境（要登录、要养号、要过风控）**必须跑在有显卡的机器上**。
无 GPU 的机器上 `getContext('webgl')` 返回 `null`，这是最明显的非真人信号。

## 二、部署 hub（在 192.168.3.5）

### 2.1 一条命令

仓库里自带了幂等部署脚本：

```bash
bash scripts/deploy-hub-35.sh
```

它做四件事：

1. 在 3.5 上建 `/opt/zhiwen-hub` 与 `/srv/zw-hub/data`
2. `rsync` 代码过去
3. 首次运行生成随机令牌写入 `.env`（已存在则沿用）
4. `docker compose up -d --build` 并验证 `/healthz`

### 2.2 手工部署（如果你想自己控制每一步）

```bash
# 在 3.5 上
sudo mkdir -p /opt/zhiwen-hub /srv/zw-hub/data
sudo chown -R $USER:$USER /opt/zhiwen-hub /srv/zw-hub/data

# 把仓库的 hub/ 目录拷到 /opt/zhiwen-hub/
cd /opt/zhiwen-hub
cp .env.example .env
# 编辑 .env，把 ZW_HUB_TOKEN 换成一个足够长的随机串
# 生成方式：python3 -c "import secrets;print('zw_'+secrets.token_urlsafe(36))"

sudo docker compose up -d --build
curl -s http://127.0.0.1:8700/healthz
```

### 2.3 验证

```bash
# 在任意内网机器上
curl -s http://192.168.3.5:8700/healthz
# {"ok":true,"data":{"status":"ok","version":"0.2.0",...}}

TOKEN=$(ssh 192.168.3.5 'sed -n "s/^ZW_HUB_TOKEN=//p" /opt/zhiwen-hub/.env')
curl -s -H "Authorization: Bearer $TOKEN" http://192.168.3.5:8700/v1/meta
curl -s -H "Authorization: Bearer $TOKEN" http://192.168.3.5:8700/v1/index
```

### 2.4 hub 的全部配置项

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZW_HUB_TOKEN` | 空 | **必填**。客户端用 `Authorization: Bearer <它>` |
| `ZW_DATA_DIR` | `/data` | 容器内数据目录（挂卷） |
| `ZW_HUB_PORT` | `8700` | 监听端口 |
| `ZW_KEEP_REVISIONS` | `10` | 每个环境保留多少个历史版本 |
| `ZW_LEASE_TTL` | `90` | 租约默认有效秒数 |
| `ZW_MAX_BLOB_BYTES` | 268435456 | 单个快照块上限（256 MiB） |
| `ZW_REQUIRE_SIGNATURE` | `false` | 是否要求请求 HMAC 签名（局域网一般不用） |
| `ZW_SIGNATURE_SECRET` | 空 | 开签名时必须配，客户端也要配同一个 |
| `ZW_ALLOWED_CIDRS` | 空 | 来源网段白名单，逗号分隔。**配了就 fail-closed**（不在名单里一律 403） |
| `ZW_SHELL_ENABLED` | `true` | 远程命令行总开关。置 `false` 后管理员侧命令接口一律 403 `SHELL_DISABLED` |
| `ZW_SHELL_MAX_OUTPUT` | `65536` | 每条命令 stdout / stderr 各自的上限（字节），超出按 UTF-8 安全边界截断 |
| `ZW_SHELL_QUEUE_LIMIT` | `200` | 每台设备排队中的命令上限，到顶返回 429 `SHELL_QUEUE_FULL` |
| `ZW_LOG_LEVEL` | `INFO` | 日志级别 |

### 2.5 数据备份

hub 的全部状态就是 `/srv/zw-hub/data` 一个目录：

```
blobs/<环境id>/v<N>.blob      加密快照
blobs/<环境id>/v<N>.meta.json 元信息
latest/<环境id>.json          最新版本指针
leases/<环境id>.json          租约
logs/hub.log
```

```bash
# 每天增量备份（加到 3.5 的 crontab）
0 3 * * * rsync -a --delete /srv/zw-hub/data/ /backup/zw-hub/
```

> 注意：这些都是**密文**，丢了就等于丢了远端副本；本地机器上还有一份完整环境，所以不算灾难。

## 三、部署 core

### 3.1 Windows（主要使用场景）

**推荐一键**（会生成 `.env`、随机令牌与主密码、自动找内核）：

```powershell
.\scripts\windows\部署.cmd
```

手工方式：

```powershell
cd zhiwen_brwo
uv venv .venv
uv pip install -e ./core

# 把配置写进 .env（推荐），或者用环境变量
# ZW_ADMIN_TOKEN / ZW_HUB_URL / ZW_HUB_TOKEN / ZW_SYNC_PASSWORD
.venv\Scripts\python -m zw_core.main
```

> `.env` 里放密钥，已在 `.gitignore` 里。**别把它提交、别发给人。**

**想给它一个固定地址给局域网用**（让别的机器能连你的 CDP 网关）：

```powershell
$env:ZW_HOST = "0.0.0.0"          # 或指定网卡 IP
$env:ZW_GATEWAY_PUBLIC_BASE = "http://192.168.3.x:8730"
```

> 设成 `0.0.0.0` 时**必须**有 `ZW_ADMIN_TOKEN`，否则程序会拒绝启动 —— 这是防止你把浏览器裸奔在局域网上。

**开机自启**：用「任务计划程序」指向 `scripts\windows\启动.cmd`，或用 `nssm` 注册成真正的服务。
细节见 `scripts/windows/安装字体与依赖说明.txt`。

### 3.2 Linux

```bash
cd zhiwen_brwo
uv venv .venv && uv pip install --python .venv/bin/python -e ./core

export ZW_ADMIN_TOKEN=...
export ZW_CHROME_BIN=/opt/bsm-p0/ungoogled-chromium-*/chrome
export ZW_CHROME_EXTRA_ARGS="--no-sandbox --disable-dev-shm-usage"
.venv/bin/python -m zw_core.main
```

systemd 单元示例（`/etc/systemd/system/zhiwen-core.service`）：

```ini
[Unit]
Description=知纹核心（zhiwen core）
After=network-online.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/zhiwen_brwo
EnvironmentFile=/opt/zhiwen_brwo/.env
ExecStart=/opt/zhiwen_brwo/.venv/bin/python -m zw_core.main
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now zhiwen-core
journalctl -u zhiwen-core -f
```

### 3.3 Docker（可选，Linux）

`core/Dockerfile` 已提供。注意容器里跑浏览器需要 `--no-sandbox`，安全上要自己权衡；
如果只是把 core 当控制面、浏览器跑在宿主上，用 `network_mode: host` 更省事。

```yaml
services:
  core:
    build: ./core
    network_mode: host
    environment:
      ZW_ROOT: /data
      ZW_ADMIN_TOKEN: ${ZW_ADMIN_TOKEN}
      ZW_HUB_URL: http://192.168.3.5:8700
      ZW_HUB_TOKEN: ${ZW_HUB_TOKEN}
      ZW_SYNC_PASSWORD: ${ZW_SYNC_PASSWORD}
      ZW_CHROME_BIN: /usr/bin/chromium
    volumes:
      - /srv/zhiwen:/data
```

## 四、core 的全部配置项

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZW_ROOT` | `%LOCALAPPDATA%\zhiwen` / `~/.local/share/zhiwen` | 数据目录（DB、环境、引擎、日志都在这） |
| `ZW_NODE_ID` | 主机名 | 节点标识，出现在租约和日志里 |
| `ZW_HOST` | `127.0.0.1` | 监听地址。改 `0.0.0.0` 必须配令牌 |
| `ZW_PORT` | `8730` | HTTP / 网关端口 |
| `ZW_ADMIN_TOKEN` | 空 | 管理令牌 |
| `ZW_GATEWAY_PUBLIC_BASE` | 自动推 | 给别人用的网关地址，例如 `http://192.168.3.x:8730` |
| `ZW_CHROME_BIN` | 空 | 指定内核路径（优先级最高） |
| `ZW_CHROME_EXTRA_ARGS` | 空 | 额外启动参数，空格分隔 |
| `ZW_PORT_POOL_START` / `_END` | `21001` / `21100` | 浏览器调试端口池 |
| `ZW_MAX_RUNNING` | `20` | 同时运行的环境上限 |
| `ZW_LAUNCH_TIMEOUT` | `45` | 启动等待秒数 |
| `ZW_ENGINE_DIR` | `<数据目录>/engines` | 内核搜索目录（递归找 chrome/chrome.exe） |
| `ZW_PROXY_RELAY` | `true` | 带认证的代理是否走本机中继（Chrome 137+ 忽略 `--load-extension`，扩展方案失效；设为 false 退回旧方案） |
| `ZW_SHELL_ENABLED` | `true` | 是否允许服务器远程执行命令（客户端界面可关） |
| `ZW_RESTORE_TABS` | `true` | 启动时恢复上次关闭的标签页 |
| `ZW_OPEN_DETECT_ON_START` | `true` | 启动后追加 IP/指纹检测页 |
| `ZW_DEFAULT_PACKS` | `true` | 新建环境是否自动带上默认扩展包 |
| `ZW_ENGINE_AUTOFETCH` | `false` | 预留：缺内核时是否自动下载（默认关，不替用户从网上拉二进制） |
| `ZW_IDLE_TIMEOUT` | `0` | 空闲回收秒数，0=不回收；**有活 CDP 连接时绝不回收** |
| `ZW_RESTORE_TABS` | `true` | 启动时恢复"上次关闭时的标签页"（关闭时用 CDP 抓，写入 `profiles.start_urls`） |
| `ZW_OPEN_DETECT_ON_START` | `true` | 启动时在恢复的标签**之后**追加检测页（出口 IP / IP 干净度 / 浏览器指纹） |
| `ZW_DETECT_URLS` | 三选自带（见下） | 检测页列表，逗号分隔。留空=用内置三个；想一个都不开请关 `ZW_OPEN_DETECT_ON_START` |
| `ZW_DEFAULT_PACKS` | `true` | 新建环境时自动带上"默认扩展包"（`is_default=1` 的包，含扩展代码与它的存储数据） |
| `ZW_RESTART_MAX_ATTEMPTS` | `3` | 崩溃自动重启的最大连续次数（防崩溃循环） |
| `ZW_RESTART_BACKOFF` | `5.0` | 重启退避基数（秒，按次数线性放大，上限 30） |
| `ZW_STOP_GRACE` | `6` | 优雅停止宽限秒数 |
| `ZW_HEALTH_INTERVAL` | `15` | 巡检间隔 |
| `ZW_CDP_TOKEN_TTL` | `900` | CDP 令牌有效期（60–7200） |
| `ZW_CDP_MAX_CONN` | `8` | 单环境并发 ws 连接上限 |
| `ZW_ALLOWED_CIDRS` | 空（不限制） | 允许访问的来源网段，逗号分隔，例如 `127.0.0.1/32,192.168.3.0/24`。**配了就 fail-closed** |
| `ZW_FORCE_TOKEN_ON_PUBLIC` | `true` | 非回环监听时强制要求令牌 |
| `ZW_HUB_URL` | 空 | 同步中心地址 |
| `ZW_HUB_TOKEN` | 空 | 同步中心令牌 |
| `ZW_SYNC_PASSWORD` | 空 | 同步主密码（**只从环境变量读，不落盘**） |
| `ZW_SYNC_ENABLED` | `true` | 总开关 |
| `ZW_SYNC_MAX_BUNDLE_BYTES` | 134217728 | 单环境快照上限（128 MiB），超了拒绝推送/导出 |
| `ZW_TRUST_PROXY_HEADERS` | `false` | 放在 nginx 后面时开，才认 `X-Forwarded-For` |
| `ZW_LOG_LEVEL` | `INFO` | 日志级别 |
| `ZW_LOG_JSON` | `false` | 控制台是否输出 JSON 行（文件永远是 JSON） |
| `ZW_LOG_KEEP_DAYS` | `14` | 日志保留天数 |

### 4.1 检测页默认值（`ZW_DETECT_URLS`）

内置三个，都是 2026-11-17 用 `curl` + 真 Chrome 渲染双重确认过"打开就有数据、不要登录、不要人机验证"：

| URL | 给什么 |
|---|---|
| `https://browserleaks.com/ip` | 出口 IP + WebRTC 泄漏（能看出代理有没有漏真实 IP） |
| `https://ip123.in/` | 中文 IP 干净度：欺诈评分、代理/VPN 特征、黑名单状态、原生/机房 IP |
| `https://abrahamjuliot.github.io/creepjs/` | 综合指纹（FP ID、fuzzy hash、WebRTC 候选、时区语言一致性） |

试过但**没有**放进默认值的：`ping0.cc`（Cloudflare Turnstile 人机验证墙，自动化打开只有验证码）、
`scamalytics.com/ip`（是查询表单，不会自动显示你自己 IP 的分数）、`ip.cn`（探到 127.0.0.1）、
`whoer.net` / `ipcheck.ing`（渲染只有"请稍候…"）。

也验证可用的备选：`https://ipinfo.io/json`（最轻，纯 JSON 出口 IP）、`https://browserleaks.com/canvas`（单独看 canvas 指纹）。

```bash
# 只要出口 IP 一个，别的都关掉
ZW_DETECT_URLS="https://ipinfo.io/json" zw restart dev
# 只恢复上次标签，不开检测页
ZW_OPEN_DETECT_ON_START=false
```

## 五、加第二台 core

1. 同样装好 core，设不同的 `ZW_PORT`（比如 8731）和**不同的** `ZW_PORT_POOL`。
2. 指向**同一个** hub（同一个 `ZW_HUB_URL` / `ZW_HUB_TOKEN` / `ZW_SYNC_PASSWORD`）。
3. 在 A 上 `zw sync push <环境>`，在 B 上 `zw sync pull <环境id>` —— B 上没有这个环境会自动导入。

**唯一的红线**：不要让两台机器同时启动同一个环境。租约会在 hub 侧拦住你（`PROFILE_BUSY`）。
如果你确认对方是死进程，可以在本地 `zw profile unlock <环境>` 强制释放**本地**租约，
但 hub 侧租约要等 TTL 过期（默认 90 秒）。

## 六、网络与防火墙

| 方向 | 端口 | 用途 |
|---|---|---|
| 局域网 → core | 8730 | 控制台 + API + CDP 网关（同一个口） |
| 局域网 → hub | 8700 | 同步中心 |
| core → hub | 出站 | 推拉快照 |
| core → 本机 | 21001–21100 | **只绑 127.0.0.1**，不对外 |

```bash
# Linux 上收一下
sudo ufw allow from 192.168.3.0/24 to any port 8730 proto tcp
sudo ufw allow from 192.168.3.0/24 to any port 8700 proto tcp
```

**不要**把 8730 / 8700 映射到公网。需要远程访问请走你现有的代理 / EasyTier，而不是开端口。
