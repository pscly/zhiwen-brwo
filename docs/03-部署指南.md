# 03 · 部署指南

> 三种部署形态，按你的实际情况选。
> 推荐：**hub 在 3.5（Docker）+ core 在 Windows（裸装）+ 以后再加节点**。

---

## 一、拓扑总览

```
        ┌──────────────────────────────────────────────┐
        │ 192.168.3.5 · zw-hub（Docker，一个容器一个卷）│
        │  :8700  同步中心：加密快照 + 租约 + 索引      │
        └───────────────▲──────────────────────────────┘
                        │ 局域网 HTTP（包体自带 AEAD）
        ┌───────────────┴───────────────┬──────────────┐
        │                               │              │
┌───────┴────────┐            ┌─────────┴──────┐  ┌────┴─────────┐
│ Windows 主开发机│            │ 192.168.3.6    │  │ 以后再加的机器 │
│  zw-core :8730 │            │  zw-core :8730 │  │              │
│  浏览器 × N     │            │  浏览器 × N     │  │              │
│  Web 控制台     │            │  （无 GPU，只跑 │  │              │
│  MCP 服务       │            │   无头任务）    │  │              │
└────────────────┘            └────────────────┘  └──────────────┘
```

**关键约束**：承担"真人身份"的环境（要登录、要养号、要过风控）**必须跑在有显卡的机器上**。
无 GPU 的机器上 `getContext('webgl')` 返回 `null`，这是最明显的非真人信号。

## 二、部署 hub（在 192.168.3.5）

### 2.1 一条命令

仓库里自带了幂等部署脚本：

```bash
bash scripts/deploy-hub-35.sh
```

它做四件事：

1. 在 3.5 上建 `/opt/zhiwen-hub` 与 `/srv/zw-hub/data`
2. `rsync` 代码过去
3. 首次运行生成随机令牌写入 `.env`（已存在则沿用）
4. `docker compose up -d --build` 并验证 `/healthz`

### 2.2 手工部署（如果你想自己控制每一步）

```bash
# 在 3.5 上
sudo mkdir -p /opt/zhiwen-hub /srv/zw-hub/data
sudo chown -R $USER:$USER /opt/zhiwen-hub /srv/zw-hub/data

# 把仓库的 hub/ 目录拷到 /opt/zhiwen-hub/
cd /opt/zhiwen-hub
cp .env.example .env
# 编辑 .env，把 ZW_HUB_TOKEN 换成一个足够长的随机串
# 生成方式：python3 -c "import secrets;print('zw_'+secrets.token_urlsafe(36))"

sudo docker compose up -d --build
curl -s http://127.0.0.1:8700/healthz
```

### 2.3 验证

```bash
# 在任意内网机器上
curl -s http://192.168.3.5:8700/healthz
# {"ok":true,"data":{"status":"ok","version":"0.2.0",...}}

TOKEN=$(ssh 192.168.3.5 'sed -n "s/^ZW_HUB_TOKEN=//p" /opt/zhiwen-hub/.env')
curl -s -H "Authorization: Bearer $TOKEN" http://192.168.3.5:8700/v1/meta
curl -s -H "Authorization: Bearer $TOKEN" http://192.168.3.5:8700/v1/index
```

### 2.4 hub 的全部配置项

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZW_HUB_TOKEN` | 空 | **必填**。客户端用 `Authorization: Bearer <它>` |
| `ZW_DATA_DIR` | `/data` | 容器内数据目录（挂卷） |
| `ZW_HUB_PORT` | `8700` | 监听端口 |
| `ZW_KEEP_REVISIONS` | `10` | 每个环境保留多少个历史版本 |
| `ZW_LEASE_TTL` | `90` | 租约默认有效秒数 |
| `ZW_MAX_BLOB_BYTES` | 268435456 | 单个快照块上限（256 MiB） |
| `ZW_REQUIRE_SIGNATURE` | `false` | 是否要求请求 HMAC 签名（局域网一般不用） |
| `ZW_SIGNATURE_SECRET` | 空 | 开签名时必须配，客户端也要配同一个 |
| `ZW_ALLOWED_CIDRS` | 空 | 来源网段白名单，逗号分隔。**配了就 fail-closed**（不在名单里一律 403） |
| `ZW_SHELL_ENABLED` | `true` | 远程命令行总开关。置 `false` 后管理员侧命令接口一律 403 `SHELL_DISABLED` |
| `ZW_SHELL_MAX_OUTPUT` | `65536` | 每条命令 stdout / stderr 各自的上限（字节），超出按 UTF-8 安全边界截断 |
| `ZW_SHELL_QUEUE_LIMIT` | `200` | 每台设备排队中的命令上限，到顶返回 429 `SHELL_QUEUE_FULL` |
| `ZW_LOG_LEVEL` | `INFO` | 日志级别 |

### 2.5 数据备份

hub 的全部状态就是 `/srv/zw-hub/data` 一个目录：

```
blobs/<环境id>/v<N>.blob      加密快照
blobs/<环境id>/v<N>.meta.json 元信息
latest/<环境id>.json          最新版本指针
leases/<环境id>.json          租约
logs/hub.log
```

```bash
# 每天增量备份（加到 3.5 的 crontab）
0 3 * * * rsync -a --delete /srv/zw-hub/data/ /backup/zw-hub/
```

> 注意：这些都是**密文**，丢了就等于丢了远端副本；本地机器上还有一份完整环境，所以不算灾难。

## 三、部署 core

### 3.1 Windows（主要使用场景）

**推荐一键**（会生成 `.env`、随机令牌与主密码、自动找内核）：

```powershell
.\scripts\windows\部署.cmd
```

手工方式：

```powershell
cd zhiwen_brwo
uv venv .venv
uv pip install -e ./core

# 把配置写进 .env（推荐），或者用环境变量
# ZW_ADMIN_TOKEN / ZW_HUB_URL / ZW_HUB_TOKEN / ZW_SYNC_PASSWORD
.venv\Scripts\python -m zw_core.main
```

> `.env` 里放密钥，已在 `.gitignore` 里。**别把它提交、别发给人。**

**想给它一个固定地址给局域网用**（让别的机器能连你的 CDP 网关）：

```powershell
$env:ZW_HOST = "0.0.0.0"          # 或指定网卡 IP
$env:ZW_GATEWAY_PUBLIC_BASE = "http://192.168.3.x:8730"
```

> 设成 `0.0.0.0` 时**必须**有 `ZW_ADMIN_TOKEN`，否则程序会拒绝启动 —— 这是防止你把浏览器裸奔在局域网上。

**开机自启**：用「任务计划程序」指向 `scripts\windows\启动.cmd`，或用 `nssm` 注册成真正的服务。
细节见 `scripts/windows/安装字体与依赖说明.txt`。

### 3.2 Linux

```bash
cd zhiwen_brwo
uv venv .venv && uv pip install --python .venv/bin/python -e ./core

export ZW_ADMIN_TOKEN=...
export ZW_CHROME_BIN=/opt/bsm-p0/ungoogled-chromium-*/chrome
export ZW_CHROME_EXTRA_ARGS="--no-sandbox --disable-dev-shm-usage"
.venv/bin/python -m zw_core.main
```

systemd 单元示例（`/etc/systemd/system/zhiwen-core.service`）：

```ini
[Unit]
Description=知纹核心（zhiwen core）
After=network-online.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/zhiwen_brwo
EnvironmentFile=/opt/zhiwen_brwo/.env
ExecStart=/opt/zhiwen_brwo/.venv/bin/python -m zw_core.main
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now zhiwen-core
journalctl -u zhiwen-core -f
```

### 3.3 Docker（可选，Linux）

`core/Dockerfile` 已提供。注意容器里跑浏览器需要 `--no-sandbox`，安全上要自己权衡；
如果只是把 core 当控制面、浏览器跑在宿主上，用 `network_mode: host` 更省事。

```yaml
services:
  core:
    build: ./core
    network_mode: host
    environment:
      ZW_ROOT: /data
      ZW_ADMIN_TOKEN: ${ZW_ADMIN_TOKEN}
      ZW_HUB_URL: http://192.168.3.5:8700
      ZW_HUB_TOKEN: ${ZW_HUB_TOKEN}
      ZW_SYNC_PASSWORD: ${ZW_SYNC_PASSWORD}
      ZW_CHROME_BIN: /usr/bin/chromium
    volumes:
      - /srv/zhiwen:/data
```

| `ZW_DEFAULT_PACKS` | `true` | 新建环境是否自动带上默认扩展包 |
| `ZW_IDLE_TIMEOUT` | `0` | 空闲回收秒数，0=不回收；**有活 CDP 连接时绝不回收** |
| `ZW_RESTORE_TABS` | `true` | 启动时恢复"上次关闭时的标签页"（关闭时用 CDP 抓，写入 `profiles.start_urls`） |

| `ZW_ALLOWED_CIDRS` | 空（不限制） | 允许访问的来源网段，逗号分隔，例如 `127.0.0.1/32,192.168.3.0/24`。**配了就 fail-closed** |
| `ZW_FORCE_TOKEN_ON_PUBLIC` | `true` | 非回环监听时强制要求令牌 |

| `ZW_HUB_TOKEN` | 空 | 同步中心令牌 |
| `ZW_SYNC_PASSWORD` | 空 | 同步主密码（**只从环境变量读，不落盘**） |
| `ZW_SYNC_ENABLED` | `true` | 总开关 |
| `ZW_SYNC_MAX_BUNDLE_BYTES` | 134217728 | 单环境快照上限（128 MiB），超了拒绝推送/导出 |

| `ZW_GATEWAY_ENABLED` | `true` | 是否登记 CDP 网关路由。设成 `false` 后 `/cdp/<id>` 一律 404，只能本机直连 `127.0.0.1:<端口>`（适合"这台机器不对外提供 CDP"） |
| `ZW_DEVICE_ID` | 空 | 设备机器码（`zwd_…`）。客户端会自动生成并写入配置；手工跑 core 需要远程访问时也可显式给 |

| `ZW_ENGINE_POLICY` | `ungoogled` | 内核策略。`ungoogled` = 只用 ungoogled-chromium（能加载命令行扩展），没有就报错/自动装，**不退回官方 Chrome**；`any` = 旧行为（引擎目录→系统 Chrome→PATH） |
| `ZW_ENGINE_AUTO_INSTALL` | `true` | 启动时没 ungoogled 内核就后台自动下载安装（约 150–200MB） |
| `ZW_ENGINE_URL` | 空 | 手动指定内核压缩包（离线/内网镜像/macOS 用）。**必须**同时给 `ZW_ENGINE_SHA256` |
| `ZW_ENGINE_SHA256` | 空 | 配合 `ZW_ENGINE_URL` 的校验值 |
| `ZW_ENGINE_VERSION_TAG` | 空 | 手动指定时的目录名（默认 `custom`） |
| `ZW_ENGINE_REPO` | 空 | 覆盖 GitHub 仓库（内网镜像/加速站） |
| `ZW_ENV_FILE` | 空 | 指定 `.env` 文件位置（不给就按「配置目录 → 当前目录」找 `zhiwen.env` / `.env`） |
| `ZW_DOWNLOAD_PROXY` | 空 | 从商店下载扩展（CRX）时用的代理，如 `http://127.0.0.1:7890`。**国内必须配**：`clients2.google.com` 直连会报 `SSL: UNEXPECTED_EOF_WHILE_READING` |
| `ZW_EGRESS_ENDPOINTS` | 三个境外地址 | 代理"检测出口"要访问的 IP 回显地址，逗号分隔。**国内网络建议自建**一个返回 `{"ip":"x.x.x.x"}` 的地址换掉它 |
| `ZW_LOG_LEVEL` | `INFO` | 日志级别 |
| `ZW_LOG_JSON` | `false` | 控制台是否输出 JSON 行（文件永远是 JSON） |
| `ZW_LOG_KEEP_DAYS` | `14` | 日志保留天数 |

> ⚠️ **`ZW_TRUST_PROXY_HEADERS` 与"本机免令牌"是一对危险组合。**
>
> 鉴权规则是"来自回环 → 免令牌"。而 HTTP 的 `X-Forwarded-For` 是**客户端可以自己写**的。
> 一旦打开这个开关，放在前面的反代若原样透传该头，任何人加一条
> `X-Forwarded-For: 127.0.0.1` 就等于自称"本机"，整个控制台不需要令牌。
>
> 打开它之前，**必须**让反代**覆盖**（而不是追加）这个头，例如 nginx：
>
> ```nginx
> proxy_set_header X-Forwarded-For $remote_addr;   # 覆盖，不是 $proxy_add_x_forwarded_for
> ```
>
> 另外，uvicorn 自带的同类行为已被我们显式关掉（`proxy_headers=False`，
> 见 `main.py` 的 `run()`）。否则本机反代转发时，uvicorn 会把 `client.host`
> 换成 XFF 里的值 —— 那条路同样能绕过"本机免令牌"的判断，
> 而且和这个开关无关，属于必须关掉的一层。

### 3.x 内核：默认用 ungoogled-chromium

官方 Google Chrome **137 起忽略 `--load-extension`**（实测 149/150/157 都不加载），
也就是说在官方内核上"把插件带进环境"只是放了文件、浏览器不认。所以本项目默认改用
**ungoogled-chromium**：

- 客户端启动时，如果没有 ungoogled 内核，会在**后台**下载安装到
  `<数据目录>/engines/<版本>/`（不阻塞启动，进度见 `GET /api/v1/engine`）
- 下载会核对 GitHub 公布的 `sha256`，**校验不通过就丢弃**，不会"先装上再说"
- 解包后自动跑一次 `--version` 自检，跑不起来会明确报错（Linux 常见缺 libnss3 等）
- 装好后 `ZW_ENGINE_POLICY=ungoogled` 下只用它，**不会悄悄退回官方 Chrome**
  （退回去等于丢掉插件能力且用户不知情）

手动操作：

```bash
zw engine status      # 当前内核、版本、能否加载扩展、下载进度
zw engine install     # 立即下载安装（--force 重装）
```

上游没有 macOS 稳定二进制；macOS 请自己下压缩包，用
`ZW_ENGINE_URL` + `ZW_ENGINE_SHA256` 指定。

### 4.0 不想设系统环境变量？用配置文件

**单文件客户端**也可以用一个文本文件配置，比改 Windows 环境变量省事得多：

1. 在配置目录新建 `zhiwen.env`
   （Windows：`%LOCALAPPDATA%\zhiwen-client\zhiwen.env`；
   Linux/macOS：`~/.config/zhiwen-client/zhiwen.env`）
2. 一行一个 `KEY=VALUE`：

   ```
   # 从商店链接装扩展要用的代理（国内必须有，clients2.google.com 直连会 SSL EOF）
   ZW_DOWNLOAD_PROXY=http://127.0.0.1:7890
   ```

3. 重开客户端生效。

查找顺序：`ZW_ENV_FILE` 指定 → 配置目录的 `zhiwen.env` / `.env` → 当前工作目录的
`zhiwen.env` / `.env`。**只读第一个找到的**，并且**不会覆盖已经存在的环境变量**
（命令行 / CI 里显式设的永远优先，Docker 行为不变）。

写法支持：`#` 注释、`export KEY=VALUE`、值两端的单/双引号会被去掉、文件可带 BOM。

### 4.1 检测页默认值（`ZW_DETECT_URLS`）

内置三个，都是 2026-11-17 用 `curl` + 真 Chrome 渲染双重确认过"打开就有数据、不要登录、不要人机验证"：

| URL | 给什么 |
|---|---|
| `https://browserleaks.com/ip` | 出口 IP + WebRTC 泄漏（能看出代理有没有漏真实 IP） |
| `https://ip123.in/` | 中文 IP 干净度：欺诈评分、代理/VPN 特征、黑名单状态、原生/机房 IP |
| `https://abrahamjuliot.github.io/creepjs/` | 综合指纹（FP ID、fuzzy hash、WebRTC 候选、时区语言一致性） |

试过但**没有**放进默认值的：`ping0.cc`（Cloudflare Turnstile 人机验证墙，自动化打开只有验证码）、
`scamalytics.com/ip`（是查询表单，不会自动显示你自己 IP 的分数）、`ip.cn`（探到 127.0.0.1）、
`whoer.net` / `ipcheck.ing`（渲染只有"请稍候…"）。

也验证可用的备选：`https://ipinfo.io/json`（最轻，纯 JSON 出口 IP）、`https://browserleaks.com/canvas`（单独看 canvas 指纹）。

```bash
# 只要出口 IP 一个，别的都关掉
ZW_DETECT_URLS="https://ipinfo.io/json" zw restart dev
# 只恢复上次标签，不开检测页
ZW_OPEN_DETECT_ON_START=false
```

## 五、加第二台 core

1. 同样装好 core，设不同的 `ZW_PORT`（比如 8731）和**不同的**
   `ZW_PORT_POOL_START` / `ZW_PORT_POOL_END`（例如 `22001` / `22100`）。

   > 注意是**两个**变量（`_START` 与 `_END`），没有叫 `ZW_PORT_POOL` 的配置项。
   > 只写一个 `ZW_PORT_POOL=22001-22040` 不会被读到，两台 core 仍会抢同一段端口。
2. 指向**同一个** hub（同一个 `ZW_HUB_URL` / `ZW_HUB_TOKEN` / `ZW_SYNC_PASSWORD`）。
3. 在 A 上 `zw sync push <环境>`，在 B 上 `zw sync pull <环境id>` —— B 上没有这个环境会自动导入。

**唯一的红线**：不要让两台机器同时启动同一个环境。租约会在 hub 侧拦住你（`PROFILE_BUSY`）。
如果你确认对方是死进程，可以在本地 `zw profile unlock <环境>` 强制释放**本地**租约，
但 hub 侧租约要等 TTL 过期（默认 90 秒）。

## 六、网络与防火墙

| 方向 | 端口 | 用途 |
|---|---|---|
| 局域网 → core | 8730 | 控制台 + API + CDP 网关（同一个口） |
| 局域网 → hub | 8700 | 同步中心 |
| core → hub | 出站 | 推拉快照 |
| core → 本机 | 21001–21100 | **只绑 127.0.0.1**，不对外 |

```bash
# Linux 上收一下
sudo ufw allow from 192.168.3.0/24 to any port 8730 proto tcp
sudo ufw allow from 192.168.3.0/24 to any port 8700 proto tcp
```

**不要**把 8730 / 8700 映射到公网。需要远程访问请走你现有的代理 / EasyTier，而不是开端口。

## 排错：客户端在跑、服务器上看着在线，但 core 连不上

**症状**（2026-11-17 在 Windows 云电脑上实际发生过）：

- 主控台里设备是 `online=True`、版本号也是新的
- 但 `实时=False`、`队列轮询=False`、`core_base` 那个地址连不上（`/healthz` 无响应）
- 结果：**远程命令和远程控制台一起失联**，只能跑到机器前处理

### 为什么会这样

心跳和 core 是**两条独立的命**：

1. 心跳跑在客户端进程里。`gui.local_summary()` 里有一句 `if not st: return {}` ——
   core 不在就返回空，**心跳本身照样成功**。所以服务器上一直显示"在线"。
2. 而远程命令（shell agent）和本机控制台（HTTP 端口）都活在 **core 的 lifespan**
   里。core 起不来，这两个就都不会有。

所以"在线"只说明客户端进程活着，不说明 core 活着。这个区分很重要。

### 两个常见原因

**1. 端口被占**（最常见）

用户手动跑过便携版、或上次没退干净，`8730` 被占。core 绑不上就退出了。

- **0.7.12 起会自动回退**：先探测端口（Windows 用 `SO_EXCLUSIVEADDRUSE`，
  不能用 `SO_REUSEADDR` —— 那边它允许重复绑定，探测会误判），
  被占就往后找 `8731…8739`，并把实际端口报给服务器
- 已经有健康实例时**直接附上去**，不起第二个、也不会把别人的服务停掉
- 老版本只能手动换端口或杀掉占用进程

查谁占着：`netstat -ano | findstr :8730` 找 PID，再 `tasklist /FI "PID eq <PID>"`。
注意**便携版的文件名和安装版不同**（如 `zhiwen-client-Windows-x64 (2).exe`），
用 `taskkill /IM zhiwen-client.exe` 杀不到它。

**2. Windows 防火墙**

新装的 exe 换了一个路径（`%LOCALAPPDATA%\Programs\ZhiwenClient\`），
Windows 会为它重新弹一次「是否允许访问网络」。没点允许 → 外部连不上 8730，
但本机一切正常。

到那台机器上把弹窗点掉，或在「Windows 防火墙 → 允许应用通过防火墙」里勾上。

### 怎么快速判断是哪一种

在那台机器的本机浏览器打开 `http://127.0.0.1:8730/`：

- 能打开 → core 活着，是**防火墙/端口回退**的问题
- 打不开 → core 没起来，看 `%LOCALAPPDATA%\zhiwen\logs\zhiwen.log`
  和客户端界面上的错误提示

### 3.y 下载内核/扩展要用的代理（很关键）

内核（约 140–200MB）和商店扩展（CRX）都从境外下载。**直连与走代理差三个数量级**，
这台机器实测（各 8 秒）：

| 路径 | 8 秒拿到 |
|---|---|
| 直连 GitHub release | 146 KB |
| 经 `http://127.0.0.1:21080` | **49.4 MB**（约 6 MB/s） |

所以配好代理是"能不能装上内核"的决定性因素，不是可选项。三种配法任选：

```bash
# ① 环境变量
ZW_DOWNLOAD_PROXY=http://127.0.0.1:21080

# ② 配置文件（更省事，见 §4.0）
#   %LOCALAPPDATA%\zhiwen-client\zhiwen.env   （Windows）
#   ~/.config/zhiwen-client/zhiwen.env        （Linux/macOS）
ZW_DOWNLOAD_PROXY=http://127.0.0.1:21080

# ③ 完全离线：自己下好压缩包
ZW_ENGINE_URL=/path/to/ungoogled-chromium.tar.xz   # 也支持 file:// 之外的 http(s)
ZW_ENGINE_SHA256=<对应 sha256>
```

`ZW_DOWNLOAD_PROXY` 同时作用于**内核下载**和**商店装扩展**，配一次两件都通。

**不配也能用**：程序会自动探一遍本机常见代理端口
（`7890` / `7891` / `7892` / `21080` / `7897` / `1080` / `10808`），
找到**真的能连通外网**的那个就用（不是只看端口开没开 —— 有一台机器 `7892` 开着
但代理不通，只看端口会挑错，然后所有下载莫名卡住）。

- 关掉自动发现：`ZW_DOWNLOAD_PROXY_AUTODETECT=false`
- 自定义候选：`ZW_DOWNLOAD_PROXY_PORTS=7890,20171`
- 想确认实际用了哪个：`GET /api/v1/engine` 里的 `download_proxy` 字段
  （`source` 为 `explicit` / `autodetect:21080` / `none`）
