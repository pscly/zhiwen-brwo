# 16 · 代理与扩展包

> 两件配套的事：**代理**（怎么导入、怎么测、怎么改、带认证怎么跑通）
> 与 **扩展包**（把某个浏览器里的插件连数据一起打包，新建时默认带上）。

---

## 一、代理：为什么带密码的代理需要"本地中继"

### 问题

Chromium 的 `--proxy-server` **不支持用户名密码**。写成
`http://user:pass@host:port` 时它会把整串当主机名，结果是连不上，
而且报错完全看不出原因。

更麻烦的是：**Chrome 137 之后已经忽略 `--load-extension`**。
（实测：Chrome 149 上用一个带 content_script 的扩展，页面里取不到标记 → 没被加载。）
所以原来"生成一个认证扩展去应答 `onAuthRequired`"的方案在新内核上会**静默失效**。

### 解法：本机中继

```
Chrome --proxy-server=http://127.0.0.1:<relay_port>   ← 无认证，引擎原生支持
        │
        ▼
知纹本地中继（只绑 127.0.0.1）
        │  在这里补 Proxy-Authorization，或做 SOCKS5 用户名密码握手
        ▼
上游代理 socks5://user:pass@host:port  /  http://user:pass@host:port
```

好处：**引擎无关**（不依赖扩展、不依赖 Chrome 版本）、可观测（中继自己知道连没连上）、
可测（单测里起假上游就能验完整握手）。

设计要点：

- 只绑 `127.0.0.1`，绝不 `0.0.0.0`（否则等于给全网开代理）
- SOCKS5 发**域名**而不是解析后的 IP，让 DNS 也走代理（否则 DNS 泄漏，指纹浏览器白做）
- 上游连不上时回 `502` 并带原因；静默断开在浏览器里表现为"一直转圈"，最难查
- 日志不含密码

开关：`ZW_PROXY_RELAY`（默认 `true`）。设为 `false` 会退回旧的扩展方案（老内核可用）。

## 二、代理库：导入 / 测试 / 换代理

### 批量导入

一行一个，支持这些写法：

| 写法 | 说明 |
|---|---|
| `socks5://user:pass@1.2.3.4:20000` | 最常用 |
| `http://user:pass@5.6.7.8:8080` | HTTP 代理 |
| `9.9.9.9:1080:user:pass` | 代理商的常见格式 |
| `user:pass@1.2.3.4:1080` | 省略协议（默认 http） |
| `10.0.0.1:3128` | 无认证 |
| `… # 香港住宅01` | 行尾备注会成为 label |

密码里的 `@`、`/`、`#` 要写成 `%40`、`%2F`、`%23`（或直接写原文，因为
"host:port:user:pass" 这种格式会按最后一个冒号切）。

**分号不会自动切分；逗号只有在写链时才切**（见第三节）——代理串里可能就有这些字符，
所以逗号只当兜底分隔符：单跳解析成功了就绝不切。要写链请优先用 `|` 或 `>>`。

```bash
curl -X POST http://127.0.0.1:8730/api/v1/proxies/import \
  -H 'Content-Type: application/json' \
  -d '{"text":"socks5://u:p@1.2.3.4:20000\n10.0.0.1:3128  # 直连"}'
```

返回里 `imported / skipped / ignored / failed` 分开计数，失败行带原因，不影响其它行。
**响应里不会出现密码。**

### 测试出口

```bash
# 测一条临时串（不用先入库）
curl -X POST http://127.0.0.1:8730/api/v1/proxies/test \
  -H 'Content-Type: application/json' -d '{"raw":"socks5://u:p@1.2.3.4:20000"}'

# 批量测库里的
curl -X POST http://127.0.0.1:8730/api/v1/proxies/test-many \
  -H 'Content-Type: application/json' -d '{"ids":[1,2,3]}'
```

socks5 的检测依赖 `httpx[socks]`（已写进 core 依赖）。

### 创建之后换代理

```bash
# 从代理库选
curl -X PUT http://127.0.0.1:8730/api/v1/profiles/<ref>/proxy \
  -H 'Content-Type: application/json' -d '{"proxy_id":3}'

# 或者直接给串（会自动入库）
curl -X PUT http://127.0.0.1:8730/api/v1/profiles/<ref>/proxy \
  -H 'Content-Type: application/json' -d '{"raw":"socks5://u:p@1.2.3.4:20000"}'

# 清除
curl -X PUT http://127.0.0.1:8730/api/v1/profiles/<ref>/proxy \
  -H 'Content-Type: application/json' -d '{}'
```

**运行中的环境不能热改**（Chromium 的 proxy 是启动期参数），返回
`restart_required: true`，先 stop 再 start。

界面上：客户端 → 环境行「代理」按钮；或 Web 控制台 → 代理页「批量导入」。

## 三、链式代理（前置 → 落地）

### 为什么需要

有些落地代理**直连永远不通**，只能经某条前置访问：

- 机场/中转提供的 SOCKS5 落地，只认前置那条线路的出口 IP；
- 代理商给的"住宅落地"绑了白名单，你的家宽 IP 不在里面，但机场可以；
- 落地在海外机房之间做跳板，机房侧只放行特定上游。

这种代理单独填进知纹，症状是**超时**（不是认证失败），而你在别的软件里填
"前置 + 落地"是通的 —— 因为那个软件会串两跳，而知纹（以及 Chromium）只会用一层。

### 怎么写

用 `|` 把两段连起来：**左边是前置，右边是落地**。

```
http://127.0.0.1:21080 | socks5://cf1b481103:51ec63a321@66.80.12.66:20000
```

顺手写的 `,` 和 `>>` 也认（同一个意思）：

```
http://127.0.0.1:21080, socks5://user:pass@66.80.12.66:20000
http://127.0.0.1:21080 >> socks5://user:pass@66.80.12.66:20000
```

两段都支持"单跳"里的所有写法，所以前置可以写成代理商那种四段简写：

```
127.0.0.1:21080:hopuser:hoppass | socks5://land:landpw@66.80.12.66:20000
```

导入时整行会作为一个代理条目入库，`hop` 字段单独存前置（含它自己的凭据）。
列表里显示成 `前置 → 落地`，两边的密码都是 `***`。

> **`|` 与 `>>` 是无条件的分隔符；`,` 是兜底。**
> 因为凭据里有真的可能带逗号（`http://u:pa,ss@h:8080`）。所以解析顺序是：
> 先认显式链 → 再按单跳解析 → 单跳失败才按逗号切。
> 换句话说：**密码里有逗号时别用逗号写链**，用 `|`。

### 只支持两跳

前置 + 落地，就两跳。写成三段（`a|b|c`）会明确报错：

```
PROXY_CHAIN_TOO_LONG：只支持两跳（前置 | 落地），这行有 3 段
```

不做任意长度链的理由：每多一跳多一层握手、多一层超时叠加、多一处"到底哪跳坏了"
的模糊地带，收益远小于排查成本。三跳及以上的诉求通常意味着"该换个落地"。

### 落地侧 DNS 依然成立

链式下 SOCKS5 的 `CONNECT` 仍然发**域名**（`ATYP=0x03`），由**落地**去解析。
前置只是把字节搬到落地，不参与解析 —— 否则 DNS 会落在前置那一侧，
等于绕过落地所在地区的解析结果，指纹浏览器最在意的 DNS 一致性就没了。
`tests/test_proxy_chain.py` 里对这一点有断言（落地收到的目标是域名而不是 IP）。

### 内部是怎么做的

`--proxy-server` 只能表达**一层**代理，所以链式**一律**走本机中继（哪怕两跳都不需要认证）：

```
Chrome --proxy-server=http://127.0.0.1:<relay_port>     ← 无认证
        │
        ▼
知纹本地中继
        │  ① CONNECT 落地:port  (+ 前置自己的 Proxy-Authorization)
        ▼
   前置代理（http 或 socks5，可带认证）
        │  ② 在这条隧道里对落地做 SOCKS5 握手 / 再发一次 CONNECT
        ▼
   落地代理（http 或 socks5，可带认证）
        │  ③ 裸字节流：浏览器 ↔ 目标
        ▼
      目标站点
```

中继里"连上某个代理"（`_connect_proxy`）与"在连接上完成握手"（`_handshake`）
是分开的两个函数，`_open_tunnel(spec, host, port)` 把它们串起来；链式就是
"先用前置开隧道，再在这条隧道上对落地握一次手"。这也是这次重构的核心：
旧实现把连接和握手焊死在 `_socks5_connect` 里，第二条连接根本没法复用。

### 排错：错在哪一跳

两跳的故障症状一模一样（超时/认证失败），所以错误信息里**一定带角色**：

| 你看到的 | 含义 | 该改什么 |
|---|---|---|
| `前置代理：连不上上游代理 127.0.0.1:21080（ConnectionRefused…）` | 前置本身没起来/端口错 | 本机代理软件、前置地址 |
| `前置代理：上游代理拒绝认证（407）` | 前置的账号密码错 | 前置凭据 |
| `落地代理：上游 SOCKS5 用户名密码认证失败` | 落地凭据错 | 落地凭据 |
| `落地代理：连不上上游代理 66.80.12.66:20000` | 前置通了，但它到不了落地 | 落地的地址/白名单 |

中继的 `stats()` 里也有 `chain`（`前置|落地`，不含凭据）、`is_chain` 与 `last_error`，
`zw proxy status` / 控制台代理页能看到。

> **已知边界（0.7.x）**：链式条目请**从代理库导入**（或 `PUT /profiles/<ref>/proxy`
> 带 `raw` 自动入库）。直接把带 `|` 的串写进环境的 `proxy` 字段时，入库前会被脱敏成
> 只留落地地址，前置就丢了 —— 那种情况会退化成"直连落地"（症状：一直超时）。
> 修这个要走 `manager.proxy_spec_for()` 的字段，不在本次改动范围内。

### 检测出口

`POST /api/v1/proxies/test` 对链式条目也照常可用：中继会临时起一个（不进端口池），
经两跳去取出口 IP，探完立刻关掉。失败时错误信息里会附上中继的具体原因
（例如"前置 407"），而不是一句笼统的"连接被重置"。

## 四、扩展包

### 是什么

一个包 = **扩展代码** + **该扩展的本地数据**（`Local Extension Settings/<id>`）。

用途就是你说的："把 RXYCDP 浏览器里的插件及其数据一起打包，以后创建浏览器默认带上"。

### 不搬什么（刻意的）

| 不搬 | 原因 |
|---|---|
| `Local Storage/leveldb` | 一个库混着所有源的键值，挑不出"只属于这个扩展"的边界，硬解析等于赌键编码 |
| `Sync Extension Settings/` | 云端权威，搬过去会被云端覆盖 |

### 用法

```bash
# 从某个已有环境导出（这就是 RXYCDP 那个场景）
curl -X POST http://127.0.0.1:8730/api/v1/packs/import \
  -H 'Content-Type: application/json' \
  -d '{"from_profile":"<环境ref>","name":"RXYCDP 全套"}'

# 设为新建环境默认带上
curl -X POST http://127.0.0.1:8730/api/v1/packs/<pack_id>/default \
  -H 'Content-Type: application/json' -d '{"enabled":true}'

# 应用到某个已有环境
curl -X POST http://127.0.0.1:8730/api/v1/profiles/<ref>/packs/apply \
  -H 'Content-Type: application/json' -d '{"pack_ids":["<pack_id>"]}'
```

界面上有两条导入路径：

| 你的情况 | 用哪个 | 怎么填 |
|---|---|---|
| 插件装在**知纹自己的环境**里 | 「从环境导入」 | 选那个环境 |
| 插件装在**别的浏览器**里（Roxy / RXYCDP / 官方 Chrome） | 「从 Chrome 目录导入」 | 填那个浏览器的用户数据目录，例如 `%LOCALAPPDATA%\Google\Chrome\User Data`（也可以直接给里面的 `Default`） |

「从 Chrome 目录导入」是他们这类场景的关键：RXYCDP/Roxy 不是知纹启动的，
它的扩展不在知纹的 profiles 目录里，而在标准 Chrome 的
`User Data/Default/Extensions/<id>/<ver>/`，数据在
`User Data/Default/Local Extension Settings/<id>/`。给个路径就能一起打包。

接口对应：
```bash
POST /api/v1/packs/import
{"from_chrome": "C:/Users/你/AppData/Local/Google/Chrome/User Data", "name": "RXYCDP 全套"}
```

开关：`ZW_DEFAULT_PACKS`（默认 `true`）控制"新建环境是否自动带上所有默认包"。

> **注意**：包存在**本机**（`<数据目录>/packs/`），不随同步包跨机。
> 换机器要重新导入一次，或者把整个 `packs/` 目录拷过去。

> **还有一个前提**：能否加载扩展取决于内核。Chrome 137+ 忽略
> `--load-extension`（见第一节），这类内核上扩展包不会被加载。
> 代理认证不依赖扩展（走本地中继），所以代理不受影响。

## 五、浏览器启动时默认打开什么

用户要的语义是：**先恢复上次关闭时的网址，再追加一个检测页**。

| 配置 | 默认 | 作用 |
|---|---|---|
| `ZW_RESTORE_TABS` | `true` | 启动时恢复上次的标签页 |
| `ZW_OPEN_DETECT_ON_START` | `true` | 追加检测页 |
| `ZW_DETECT_URLS` | 见下 | 检测页列表（逗号分隔） |

怎么"记住"上次的标签：**关浏览器之前**用 CDP `Target.getTargets` 抓一次
（浏览器级命令，不 attach、不改状态），写回 `start_urls`。
不去解析 Chromium 的 `Sessions/*.bin` —— 那是二进制私有格式，逆它等于给自己埋雷。

默认检测页（都实测过能打开且真的显示数据）：

| 网址 | 看什么 |
|---|---|
| `https://browserleaks.com/ip` | 出口 IP + WebRTC 泄漏 |
| `https://ip123.in/` | 中文界面的 IP 纯净度（欺诈评分/代理特征/黑名单/是否原生 IP） |
| `https://abrahamjuliot.github.io/creepjs/` | 综合指纹（FP ID、fuzzy hash） |

被剔除的（实测不可用）：`ping0.cc`（Cloudflare 验证墙）、
`scamalytics.com/ip`（是查询表单，不自动显示自己）、`ip.cn`（探到 127.0.0.1）、
`whoer.net`（只有"请稍候…"）。

调用方显式传了 `urls` 时**不追加**检测页（脚本/AI 想开指定页面就该照做）。

### 四、代理串的格式校验（0.7.5）

填错代理以前是**静默失败**：串被原样收下、存进库、显示在界面上，然后浏览器起来没有网络，
任何地方都没有提示。用户真实踩过这一条：

```
socks5://cf1b481103:51ec63a321@66.80.12 0.66:20000
                                    ↑   ↑
                                 空格   IP 五段
```

现在解析时就会拒掉，并说清错在哪：

| 情况 | 错误码 | 提示 |
|---|---|---|
| 主机名里有空格/制表符 | `PROXY_INVALID_HOST` | 会点明"是不是把 `66.80.12.66` 写成了 `66.80.12 0.66`" |
| 形似 IP 但不是四段 | `PROXY_INVALID_HOST` | `IP 应该是 4 段（a.b.c.d），现在有 5 段` |
| 某段不在 0-255 | `PROXY_INVALID_HOST` | `IP 段不合法：「999」` |
| 方括号里不是合法 IPv6 | `PROXY_INVALID_HOST` | `方括号里必须是合法 IPv6，例如 [::1]` |
| 端口不是数字 / 越界 | `PROXY_INVALID` / `PROXY_INVALID_PORT` | — |

三条入口都拦：**导入时**（`import_batch` 的 `failed` 里给出脱敏原因）、
**绑定到环境时**（`assign_to_profile` 返回 `ok=false` + 错误码）、
**启动时**（`mgr.start` 抛 `PROXY_INVALID_HOST`，而不是起一个没网的浏览器）。

主控台也看得见：代理列显示红色的「代理无效」，点开是具体原因和改法 ——
不用等用户去点"启动"才发现。错误信息里的密码永远是 `***`。

IPv6 字面量（`socks5://[::1]:1080`）是支持的。
