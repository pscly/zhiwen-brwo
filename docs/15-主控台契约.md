# 15 · 主控台契约（`:8700/`）

> `http://<服务器>:8700/` 就是主控台：登录后能看**机器**、**浏览器**、**令牌**，
> 也能直接操作。AI 用同一批接口。

## 一、页面与路由

| 路径 | 说明 |
|---|---|
| `/` | **主控台**（未登录显示登录框，登录后显示仪表盘） |
| `/panel` | 旧地址，**永久 302 到 `/`**（书签不断） |
| `/healthz` `/readyz` | 探针（不需要登录） |
| `/v1/*` | 设备与同步接口（设备用 `X-ZW-Device`，管理员用 cookie/Bearer） |

登录：面板账号密码（`ZW_PANEL_USER` / `ZW_PANEL_PASSWORD`）。
会话：HMAC 签名的 httponly cookie，7 天。

## 二、设备上报什么（心跳里带）

设备每次心跳上报（字段都可选，缺了按"未知"处理）：

```json
{
  "profiles": 3,
  "running": 1,
  "max_running": 8,
  "disk_human": "1.2GB",
  "engine": "Chrome 149.0.7827.53",
  "shell_enabled": true,
  "core_base": "http://192.168.3.6:8730",
  "inventory": [
    {"id": "56c88eb236e54eef", "name": "环境A", "state": "running", "group": "默认", "cdp_path": "/cdp/56c88eb236e54eef"}
  ]
}
```

- `core_base`：这台机器上的 core 在局域网里的地址（NAT 后面的机器填了也没用，主控台会标注"不可直连"）
- `inventory`：这台机器上有哪些浏览器环境。**只报元信息，不报 cookie/密码**
- `cdp_path`：相对 core_base 的路径；主控台据此拼出可点的 http / ws 地址

## 三、主控台接口（管理员鉴权）

鉴权：面板会话 cookie **或** `Authorization: Bearer <ZW_HUB_TOKEN>`。

### `GET /v1/console/overview`

主控台首屏一次拉完。形状：

```json
{"ok": true, "data": {
  "server": {
    "version": "0.4.2", "uptime_seconds": 3600, "data_dir": "/data",
    "shell_enabled": true, "token_required": false,
    "auto_approve": true, "allowed_cidrs": ["192.168.3.0/24"],
    "default_credentials": false
  },
  "totals": {"machines": 2, "online": 1, "browsers": 5, "running": 2},
  "machines": [{
    "device_id": "zwd_...", "label": "psubs3.6", "hostname": "psubs3.6",
    "platform": "Windows", "arch": "AMD64", "app_version": "0.4.1",
    "status": "active", "online": true, "last_seen_ago": 12,
    "last_ip": "192.168.3.1", "shell_enabled": true,
    "profiles": 3, "running": 1, "max_running": 8,
    "disk_human": "1.2GB", "engine": "Chrome 149",
    "core_base": "http://192.168.3.6:8730",
    "core_reachable": null,
    "shell_last_poll_ago": 3.2,
    "shell_polling": true,
    "browsers": [{
      "id": "56c88eb2...", "name": "环境A", "state": "running", "group": "默认",
      "cdp_http": "http://192.168.3.6:8730/cdp/56c88eb2...",
      "cdp_ws": "ws://192.168.3.6:8730/cdp/56c88eb2.../devtools/browser/..."
    }]
  }],
  "events": [{"ts": 1794836000.0, "action": "enroll", "device_id": "zwd_...", "by": "", "note": ""}]
}}
```

- `online`：180 秒内有心跳
- `core_reachable`：`true`/`false`/`null`。hub 会**尽力探测一次**（300ms 超时）；
  `null` 表示没配 core_base。探测失败不影响接口返回。
- `browsers` 没有上报时是 `[]`（不是 null）
- **绝不含任何密钥原文**

### `POST /v1/console/machines/{device_id}/approve`

允许一台设备接入（`pending` / `rejected` → `active`）。

### `POST /v1/console/machines/{device_id}/reject`

拒绝接入。**不是删除**：记录保留，随时可以再允许。
拒绝后该设备的同步与心跳会被 403（`DEVICE_REJECTED`），但**远程终端仍可用**。

### `GET /v1/console/secrets`

令牌/凭据区用。**这是敏感接口**，只在面板会话或用 Bearer 令牌时可用：

```json
{"ok": true, "data": {
  "panel_user": "pscly",
  "panel_password": "……",
  "hub_token": "…… 或空串",
  "hub_token_set": true,
  "allowed_cidrs": ["192.168.3.0/24"],
  "auto_approve": true,
  "sync_password_set": false,
  "hint": "这些是本机 .env 里的值；面板只在本机/局域网内可用，别透到公网"
}}
```

> 之所以真的返回原文：用户明确要"能看到令牌"。它已经受"面板密码 + 网段白名单"保护，
> 而且和 `.env` 里的东西等价 —— 能登面板的人本来就能改服务器。
> 但接口必须显式标注敏感，且**不允许跨域**、**不进日志**。

### `POST /v1/console/machines/{device_id}/note`

改备注（`{"note": "客厅主机"}`）。等同 `/panel/api/devices/{id}/label`，保留旧接口。

## 四、AI 怎么用

`GET /v1/ai/manifest` 里会列出：本文档的端点、每个端点的用途，
以及"想知道有哪些机器/浏览器 → 调 `/v1/console/overview`"这条指引。

AI 的标准动作序列：

1. `GET /v1/console/overview` → 拿到机器与浏览器清单（含 cdp_http / cdp_ws）
2. 要操作某台机器 → `POST /v1/devices/{id}/shell`（见 `docs/13`）
3. 要操作某个浏览器 → 用该浏览器的 `cdp_ws`（局域网可达时）或先在那台机器上跑命令

## 五、页面结构（给 UI 实现）

```
顶栏：知纹 · 机群控制台   [机器] [浏览器] [令牌] [事件]     已连接/刷新/退出
────────────────────────────────────────────────────────
① 机器    卡片列表：主机名 / 平台 / 版本 / 在线 / 环境数 / 命令行开关
          操作：终端、踢下线、恢复、改名、打开控制台（core_base）
② 浏览器  按机器分组：环境名 / 状态 / 分组 / CDP 地址（可点、可复制）
          操作：复制 cdp_http、复制 cdp_ws、打开
③ 令牌    面板账号、面板密码、hub 令牌、网段白名单、自动放行开关
          每个都能"显示/隐藏 + 复制"；顶部一条安全提示
④ 事件    谁注册/踢了/恢复了，最近 50 条
```

要求：
- 登录页与主控台**同一个页面**（未登录时只显示登录框）
- 输出/名称一律转义（设备名、备注、环境名都可能是用户输入）
- 不引入外部 JS/CSS/CDN
- 不用 `alert`/`confirm`/`prompt`
- 深色/浅色都成立
- 移动端能用（窄屏卡片竖排）
